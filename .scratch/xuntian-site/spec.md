# 规格：按巡天黑客松网站的结构，补齐深度研究评测基准的资料站和程序

**Status:** ready-for-agent

依据：`research-plan/site-mapping.md`（资料与程序对照巡天网站结构）第七节的待办。巡天网站代码在 `~/projects/GOSIM/shenzhen26/survey26/survey26-new/hackathon-survey26`，只作参照，不改它。

## Problem Statement

深度研究评测基准已有规则手册、出题手册、论文、文献、试评数据和一个本地资料站，但按巡天黑客松网站的结构对照，29 项里只有 6 项能直接用：赛事说明、上手、公告、名次页、复核包浏览页、参赛队伍的技术文档都没有；计分程序停在第 1.1 版；统一运行智能体和存档被引网页的程序还没有；试评时交给评委的提示词没有存成文件，而规则要求复核包公开全部评委提示词。出题同学、参赛队伍、评委和主办方各自找不到"从哪里开始"，也看不到一次完整评审的结果长什么样。

## Solution

在本地资料站里按巡天的页面结构补齐公开页面和名次、复核包页面，用第五阶段试评的真实数据做出样子；把计分程序升到第 1.2 版并配上测试；写出统一运行程序和网页存档程序；存档评委提示词；把从 MLPerf 借来的四条规则以〔默认〕写进规则手册，并加上版本变更记录。所有页面都是双击能打开的本地静态文件，不需要账号和服务器。

## Implementation Decisions

- **计分程序**：在现有试评计分程序上增加第 1.2 版，第 1.0、1.1 版的行为不变。第 1.2 版增加两条：要点的重要性或层级可以带一个"有争议"的候选列表，比较一对报告时按对领先一方最不利的候选计分；重抽样只在至少一份报告写到的要点中进行。分开的标准、名次区间公式不变。
- **计分结果导出**：计分程序能把名次区间、三种权重下的净分、严重问题、环节档位、分开的对写成一个结果文件，供页面生成器读取。
- **页面生成器**：一个生成器读取试评数据和计分结果，生成名次页、每份报告的复核页、要点池页。页面是静态 HTML，沿用资料站的视觉规则（命名文字样式、固定间距档位、减速动效曲线、深浅两套颜色），不依赖网络也能读（字体可以联网加载，失败时回退系统字体）。
- **产品名**：试评报告用匿名编号 A 至 F，旁边注明对应产品，页面显著位置写"试评演示，不是对产品的评价"。论文和一页总结已经公开了这层对应。
- **评委提示词**：从本次会话记录中原样取出第五阶段每次评委运行的任务提示，存为文件，并写一份清单把每个评委输出文件对应到提示词、模型和日期。把输出整理成文件的三个辅助脚本一并存档。会话记录路径：`~/.claude/projects/-Users-zonghuanwu-projects-GOSIM-elite-game/efdc4f00-f3cf-4541-917e-bb46cf1f48bb.jsonl`；辅助脚本在会话临时目录 `/private/tmp/claude-501/-Users-zonghuanwu-projects-GOSIM-elite-game/efdc4f00-f3cf-4541-917e-bb46cf1f48bb/scratchpad/`。
- **规则手册**：四条新规则都标〔默认〕；手册升为草案第 3 版；新增一个附录"版本变更记录"，列出规则草案第 1 至 3 版和评法第 1.0、1.1、1.2 版各改了什么、为什么。改源文件，再运行网页生成脚本。
- **统一运行程序**：支持两种调用方式。命令行方式：启动申报的命令，把题目原文从标准输入交给它，读标准输出作为报告。网络接口方式：向申报的地址发送题目，取回报告。智能体若返回"反问"，程序回复规则手册附录二的统一答复一次，并记下问题。每次运行新开进程或新请求，记录输入校验值是否与题目文本一致、起止时间、退出状态、是否超时，按附录四的列写运行记录。
- **网页存档程序**：从报告（Markdown 或 HTML）里提取网址，逐个取回，保存内容和一份清单（网址、最终网址、状态码、内容类型、字节数、校验值、取回时间、错误原因）。单个网址失败不中断。不调用任何第三方存档服务。
- **新页面**：赛事说明、上手、公告、常见问题、参赛队伍技术文档，以及新手包。未定的日期、奖项、联系方式标〔待定〕；依赖〔默认〕条款的地方注明。
- **资料站接入**：首页导航和资料库加入新页面入口，页脚加行为准则、联系方式、数据许可；对照表把完成的项目改为"已有"。
- **模型调用层**：一个模块统一调用三家命令行，另有回放方式供测试使用。每次调用写一条记录（任务名、厂商、模型、工具限定、提示词全文、回答全文、起止时间、校验值），存成按运行分开的记录文件，随复核包公开。命令行的非交互用法和关闭工具的参数由实现者查各工具的帮助确定；不读取任何密钥，用的是本机已登录的账号。
- **工具限定**：两档。只给材料：模型不能上网、不能运行命令、不能写文件。只读网页：只允许检索和读网页。评审各步用第一档；出题调研、来源核验在没有存档时用第二档。
- **模拟出题者**：输入话题和提问者设定（也可只给领域，让模型按出题手册的条件选题）。按出题手册七步：写评委版题目卡；写提问版和裸题版；两次独立调用各写深度地图的核心要点（只读网页），合并并按数鱼的办法估计总数；另一个模型只看两个交给智能体的版本做泄露检查；换一家模型、不联网做闭卷对照。输出一个题目目录：题目卡三个版本、深度地图、两人对照记录、泄露检查记录、闭卷对照记录、深度地图校验值、调用记录。
- **模拟评审**：输入题目目录、报告和网页存档。评委提示词以第五阶段存档的提示词为起点改写。各步可配置用哪几家、每家几次；判定取多数或中位数；没有一种意见达到三分之二的层级或重要性判定记为有争议，写成计分程序第 1.2 版能读的候选列表。要点池判定时隐去要点出处。最后调用计分程序，产出结果文件。
- **网站上的模拟页面**：题库页和评审记录页由生成器从输出目录生成；每次模型调用都能点开看原文，类似 HELM 的做法。
- **演示运行**：先只算出将要发起的调用次数并写进报告，再在调用次数上限内真跑；出题用淡水湖以外的一个新话题，评审用试评的六份报告和原来的题目卡、深度地图。

## Testing Decisions

- 好的测试只看对外行为：命令行的输入输出、生成的文件、计分结果，不测内部函数怎么写。期望值来自独立来源：已有的试评结果文件、"一道题走完全程"里手算并经程序复核过的示意名次。
- 计分程序：测第 1.1 版在试评数据上重现已有结果文件里的名次区间；测第 1.2 版在"一道题走完全程"的示意数据上得出三号第 1、二号和四号第 2 至 3、一号第 4、五号第 5；测有争议标注会让本来分开的一对变成并列；测深度地图上没人写到的要点不改变名次；测第五阶段 8 条验收标准的通过情况与第五阶段报告一致。
- 页面生成器：测生成的每个页面存在、本地链接都能打开、名次页包含六份报告和演示声明、每份报告页包含它的全部主要结论。
- 运行程序：用假的智能体（一个回显程序、一个会反问的程序、一个超时的程序、一个本地网络接口）测报告、运行记录和统一答复。
- 存档程序：用本地测试服务器测成功、重定向、404 和超时四种情况。
- 文档页面：测必备章节存在、本地链接都能打开。
- 统一用 Python 自带的 `unittest`，测试放在仓库根目录的 `tests/`。
- 模型调用层、模拟出题者、模拟评审的测试一律用回放方式和假的命令行程序，不真的调用模型。要测：调用记录字段齐全；工具限定的参数确实传给了命令行；泄露检查的提示词里不含深度地图；要点池判定的提示词里不含报告编号；三分之二规则正确标出争议；数鱼估计的计算正确。

## Out of Scope

- 欧盟法规题的深度地图：出题手册规定要等运行日期定下以后按截止日写。
- 正式比赛题目：要由两位出题人独立出题、保密。
- 在巡天平台代码上改造账号、提交、数据库、管理后台：那是真正办赛时的事，涉及另一个仓库。
- 账号、控制台、通知、找队友等需要服务器的页面。
- 在网页上点按钮触发模拟运行：模拟程序先用命令行运行，网页只展示结果。
- 确认规则里的〔默认〕条款：由主办方决定。
