0结论先行

  • DRB II 把"评一份开放式研究报告"变成了"对照一篇专家综述对答案"。每道题都是从一篇综述倒推出来的，评分要点是从这篇综述里拆出来的原子事实和观点。
  • 打分本身很可靠：要点自带答案，评委只需比对，和人工标注的一致率 91.75%。
  • "分数能说明什么"这一侧很弱：
    • 题目基本是原文提纲；
    • 评分只算和原文的重合，说错不扣分；
    • 原文本身的正确性和完整性没有被检验；
    • "Agent 远逊于人类专家"这一结论有一部分是筛选规则造出来的。
  • 适合的用法：当作"对照专家综述的事实召回率"这一诊断指标。不适合当深度研究能力的总排名。
  • 时效性：评分要点自 2025-11 发布以来从未改动。题目的截止年份集中在 2020–2024，随着时间推移，测记忆的成分会越来越大。

1它做了什么

  1. 选文。以初代 DeepResearch Bench 的题目为种子，找回答相似问题的开放获取综述（CC-4.0 许可），按四条适配性人工筛选，留下 132 篇。
  2. 出题和拆要点。一个 LLM 读原文，倒推出一道题，再把原文内容拆成"信息召回 / 分析 / 呈现"三个维度的二元要点。论文称这个 LLM 为 task-generator，没有披露具体是哪个模型。
  3. 自检。用原文给这些要点打分，信息召回或分析的通过率低于 90% 就重新生成。
  4. 人工清理和专家审核。论文说专家审核超过 400 小时，但没写专家人数、资质和专家间一致性。
  5. 评测。
    • 评委是 Gemini-2.5-Pro，每批判 50 条要点，每条打 1 / 0 / −1。
    • 一道题的得分 = 该题所有要点的通过率，总分 = 132 道题的平均。
    • 题目里附一段"禁止查看原文"的规则。引用了原文的句子记 −1，不计入得分。

3底层逻辑：信任的三次转移

论文第 1、2 节的推理是这样的：

  1. 它要解决的问题：开放式报告评测里，评委不知道正确答案。
    • 像"说明了婴儿肌无力的常见原因"这种粗粒度要点，只能查"写没写到这个话题"，查不了"写得对不对"。
    • 引用核验只能查"引文支不支持这句话"，查不了"引文本身对不对"。
  2. 解法：让每条要点自带答案。比如写成"指出小城市人才外流的原因是职业结构错配"。这样评委只需要比对，不需要懂这个领域。
  3. 答案从哪来：借一篇已经回答过这个问题的专家综述。开放题的标准答案要事先写对、写全，成本极高，所以直接拿现成的。
  4. 信任从哪来：借发表过程。
These reports are typically written by domain experts over the course of weeks or months and undergo multiple layers of validation—from peer reviewers, editors, practitioners, and the general public—thus reflecting a high degree of credibility and expert consensus.§3.1.1

所以信任是一路转移过来的：评委 → 标准答案 → 发表过程。整套方法立在一个假设上：这篇文章 ≈ 这道题的正确且完整的答案。论文对这个假设只给了上面这段声明，没有给证据。

4种子文章怎么选（§3.1.1）

环节规则说明了什么
起点用初代 DeepResearch Bench 的题当种子，去找回答相似问题的开放获取综述话题分布继承自初代对真实用户查询的统计
来源门槛"知名期刊、顶会、可信的机构出版物"只是一句声明，没有可检验的标准
许可只要 CC-4.0 或 CC-4.0-NC这一条实际决定了候选池，结果一半是 MDPI
四条适配性
  • 需要大量公开检索
  • 结论需要实质综合
  • 不依赖实验
  • 不依赖复杂数据挖掘或随机 ML
四条都在问"能不能出成题"，没有一条在问"文章对不对"

论文没有做的事：

  • 没有设被引门槛；
  • 没有查撤稿和更正；
  • 没有看文章是不是系统综述（系统综述有检索协议，完整性可以审计）；
  • 没有说明为什么偏偏选了这一篇，而不是同一问题下的其他综述。

从文章切出题目

  • 可以只取一节或一张表，优先取"数据召回和整理"的部分（第 2 条）。
  • 可以避开太主观的部分，原文给的理由是：
since a model is unlikely to reproduce the exact same analysis.附录 E.1 第 2 条
  • 关键数据要规定好组织方式，比如表格有哪几列；含糊的概念要给出严格定义（第 3 条）。
  • 必须既有收集，也有轻度分析，不能要求重计算（第 4 条）。
  • 模仿非专家用户的口吻，假定用户叫不出领域内的方法和细节（第 5 条）。
  • 变化快的话题要写明截止日期，和原文的时间范围对齐（第 6 条）。
  • 要点控制在 50–200 条。太多时缩小题目范围，而不是删要点（第 9 条）。

从文章拆出要点

  • 尽量全，覆盖整道题（第 7 条）。
  • 每个数值单独一条，需要计算得出的数值允许误差（第 8 条）。
  • 写出具体内容，而不是只写话题（第 10 条）。
  • 拆到不可再分（第 11 条）。
  • 引用别的研究时写出完整标题（第 12 条）。
  • 各条互相独立（第 13 条）。

三个维度

  • 信息召回：对应事实。
  • 分析：对应观点，提示词要求"结论与人类文章相似"。
  • 呈现：对应格式。

规则之间有冲突，实际执行的是"按答案裁题"。第 5 条要求像非专家用户那样提问，但附录给的示例 2 在题目里直接列出了 13 个灵敏放大器的缩写，还规定了表格列名和行数。

6弱在哪：拆开论证链

一个分数要能支撑结论，中间每一环都得成立。按 Kane 的论证式效度框架，可以拆成四环：

环节要成立的命题表现依据
① 打分评委判"这条要点过没过"判得准强要点自带答案，评委只需比对。Gemini-2.5-Pro 和人工标注的一致率 91.75%，F1 89.57
② 泛化132 道题能代表"深度研究任务"这个总体中偏弱
  • 一半来源是 MDPI；
  • 22 个领域里 15 个只有 2–6 题；
  • 每个 Agent 只跑一次；
  • 排名不给置信区间，第 5、6 名只差 0.02 分。
③ 外推得分高 = 深度研究能力强弱题目基本是原文提纲；评分只看和原文重合多少；说错不扣分
④ 结论"最强 Agent 不到 50%，远逊于人类专家"最弱原文在自己的要点上必然拿 90% 以上，这是筛选规则保证的；论文也没有拿专家盲评排序来验证 DRB II 的分数

一句话：它很客观，但客观地测量了一个偏掉的东西。客观性（评分可靠）和效度（测的是想测的东西）是两回事，DRB II 是典型例子。

6.1 完整性：靠"按答案裁题"得来，不需要证明

  • 第 2、3、9 条合起来，就是把题目裁成原文的形状：题目只问原文答了的部分，所以在这个范围里，原文按定义就是完整的。
  • 这样做的代价是题目读起来像原文提纲，测的是"按提纲把内容找回来"，测不到 Agent 自己界定问题的能力。

6.2 权威性：借来的，从没核验过

  • 90% 自检只检验"要点忠于原文"，不检验原文本身对不对。
  • 专家被要求保证要点"与原文完全一致"（remain fully consistent with the source article）。他们核对的是抽取有没有出错，不是文章有没有出错。
  • 400 小时审 9,415 条，平均每条约 2.5 分钟。

6.3 评分只算召回，不算对错

评分提示词（附录 E.2）只有三档：

  • 1：满足这条要点；
  • 0：完全没提到（does NOT mention this rubric item at all）；
  • −1：引用了被屏蔽的原文。

问题有两个：

  • 没有"提到了但说错"这一档，说错不比不说更吃亏。
  • 要点之外的内容完全不查，写得多不吃亏。

论文的出发点是"验证所召回信息的正确性"，但这个评分实际测的是"和原文重合了多少"。这和 Why LMs Hallucinate 的结论相反：只奖励命中、不惩罚说错的评分，会鼓励猜。

6.4 按范例对答案，而不是按标准判对错

第 5 题：分散投资需要几只股票
  • 题目要求整理 1968–2021 年的"代表性研究"。
  • 评分要点却逐条规定了是哪几篇：Evans & Archer 1968、Fielitz 1974、Solnik 1974、Statman 1987……每篇的市场、时段、方法、结论都要对上。
  • 如果 Agent 选了同样有代表性的其他研究（比如 Elton & Gruber 1977、Campbell 等 2001），每篇都得 0 分。
  • "哪些研究算代表性"是这篇综述作者自己的取舍，结果被当成了唯一答案。
第 117 题：吉藏的佛性论
  • 分析维度的要点里有"把'第一义空'重新诠释为一种智慧境界，而非客观真理命题"这类表述。
  • 这是一位学者的解读。别的学者换一种诠释框架，只要言之成理，照样得 0 分。
第 120 题：北地中海旅游分布 2010–2020
  • 186 条信息召回要点：13 条国土面积，140 条逐年入境人数，33 条指数值。
  • Agent 换一个同样合理的数据源（统计数据常被回头修订），这些要点就大面积丢分。
  • 题目限定 2010–2020 年，分析要点里却要求提到 2006 年的波动，而这只有原文（覆盖 2004–2020 年）写到。

三个例子是同一个毛病：和范例一样才得分，不一样就算缺失。

6.5 "与人类专家的差距"有一部分是循环论证

  • 原文按构造必然在自己的要点上拿 90% 以上。用这个上限去对比 Agent 的不到 50%，差距里有一部分来自"要点就是从原文拆出来的"。
  • 要支撑"Agent 不如专家"，至少需要另一位专家在同样条件下重做这道题，再用同一套要点去评。论文没有做。

6.6 统计与验证

  • 每个系统只跑一次，没有重复运行，也没有置信区间。排名相邻的系统差距在 0.02–2.6 分之间。
  • "各领域之间表现无显著差异（p>0.05）"：每个领域只有 2–6 题（科技 23 题除外），这个检验本来就没有能力测出差异，说明不了什么。
  • 评委只在 10 份报告上验证过，测的是"单条要点判得对不对"。论文没有检验"DRB II 分高的报告，专家是否也认为更好"。
  • 评委 Gemini-2.5-Pro 和其中两个被测系统同属 Gemini 家族。对比对类判断，这个影响可能不大，但论文没有讨论。

6.7 泄漏

  • 屏蔽规则写在题目里，本意是禁止查看，但等于把原文标题告诉了 Agent。
  • 论文报告的泄漏率在 0.24%（Grok）到 13.2%（Qwen）之间，平均 3.64%。
  • 屏蔽清单只列了原文的几个 URL，没有屏蔽 GitHub 仓库和 HuggingFace 数据集页面，而带答案的评分要点就在那里（见第 7 节）。

7时效性

三个版本的 tasks_and_rubrics.jsonl，我逐字段比对过，题目、评分要点和屏蔽清单完全一致：

  • 2025-11-17：首发；
  • 2026-02-24：加了 license 字段；
  • 2026-05-14：重写了文件，没有实质改动。

论文 2026-09 出了 v3，数据也没有跟着更新。

题数171115202224716

作者给题目加截止年份，就是为了让答案固定下来。"截至 2021 年的土地出让收入"这种事实不会变，所以要点本身不会过期。真正随时间失效的是下面四件事：

  1. 越来越能靠记忆答出来。
    • 来源文章大多发表于 2020–2025 年，早已进了训练数据。
    • 数据集 2026-02 上了 HuggingFace，评分要点全文公开，之后的模型可能直接学到。
    • LiveBrowseComp 测过：在 BrowseComp 上，Agent 不联网就能答对 44.5%。
    • DRB II 从没报告过不联网的基线分，所以分不清得分是查出来的，还是本来就记得的。
  2. 评分要点本身就在网上，可能被搜到。Search-Time Contamination 测出，这类泄漏最多能把成绩抬高 4%。原文的镜像和引用页也会越来越多，而屏蔽清单是固定的那几个链接。
  3. 网页和数据在变，评分要点没跟着变。统计数据会被修订，网页会失效。同一个 Agent、同一套要点，隔一年再测，分数可能就变了，而 Agent 本身并没有变。
  4. 全是历史题，测不到"找最新信息"。真实用户问的多半是"现在怎么样"。这要求 Agent 能识别信息过时、处理新旧说法打架。

文件夹里的论文有三种补救思路：

思路做法能解决解决不了
实时出题（LiveBrowseComp）答案只依赖出题前 90 天内的新事实，不联网的准确率低于 2%记忆污染题目过期很快，要持续出新题
冻结语料（BrowseComp-Plus、DR³-Eval）把可搜索的网页固定成一个快照网页漂移记忆污染
题目明确要求时效性（DailyReport，同一组人做的）150 道时效性强的日常任务能测"找最新信息"摘要里没说会定期换题

8它做对了什么

  • 评委不懂领域就判不准，这个问题是真实的。"要点自带答案"确实解决了它，这个思路值得借鉴。
  • 用真实专家文章做锚点，比让 LLM 自己想象评分标准好。初代 DeepResearch Bench 的标准就是 LLM 生成的。
  • 要点细到单条事实，诊断信息丰富。能看出哪类事实召回不到，也能看出差距主要在召回（23–40 分），不在呈现（75–92 分）。
  • 数据、评分脚本和提示词全部公开。本文的每个数字都能复核，这本身就值得肯定。

9怎么改，对我们有什么用

把"按范例对答案"改成"按标准判对错"

要证明的方法
文章本身可信每篇建一份来源档案：
  • 期刊和审稿方式；
  • 按领域归一化的被引百分位；
  • 撤稿和更正记录（Crossref / Retraction Watch）；
  • PubPeer 上的质疑；
  • 作者在该领域的发表记录；
  • 利益冲突。
设门槛入选。
要点正确
  • 每条要点追溯到原文引用的一手来源。
  • 分层抽样审计，比如抽 100 条估计错误率，误差约 ±10%。
  • 按出处分成"有一手来源的数据 / 作者的推论 / 无引用的断言"三类，只有第一类当硬事实。
要点必要请专家组用 Lawshe 内容效度比（CVR），对每条判"必需 / 有用 / 不必要"，过阈值才保留，并报告专家间一致性
答案完整
  1. 优先选系统综述。它有 PRISMA 检索协议，完整性可以相对于检索范围来审计。
  2. 专家在看原文之前先独立列出要点，避免被原文锚定，再和原文比对。
  3. 用捕获–再捕获估计漏了多少：拿原文的要点集和一个独立来源比对，比如专家清单或 Agent 报告里核验为真的断言，用 Lincoln–Petersen 公式估计总数。
  4. 同一问题找两篇以上独立综述，共识部分作核心要点，只有一篇提到的降权。
列举类可替换改成按条件判，比如"列出至少 k 项符合条件 X 的研究，每项经核验属实"，而不是固定一份名单
观点可接受不按"与原文相似"判，按"有证据支撑、推理成立"判，人文题尤其如此
评分有效
  • 增加"提到但错误"一档并扣分；
  • 对要点之外的断言抽查精确率；
  • 用专家盲评排序做外部检验；
  • 多跑几次并给置信区间。

对"同一 Prompt、20 个 Agent"场景的启示

  • 可以直接借鉴的：
    • 题目写法：时间范围 + 编号子问题 + 格式要求；
    • "要点自带答案、拆到不可再分"的写法。
  • 可以直接拿一道 DRB II 的题当共享 Prompt。这样现成就有约 70 条要点，还有一篇人类专家文章可以匿名混进 20 份报告里一起评。代价有三个：
    • 先要做不联网的基线测试，确认 Agent 没背过；
    • 要在搜索层面屏蔽原文和数据集页面，光靠提示词不够；
    • 仍然要把 20 份报告的断言汇总起来，补进原文没写、但核验为真的内容。
  • 更稳妥的是自己出新题。
    • 截止日期定在运行当天；
    • 专家在运行前先写好必答清单，运行后把 20 份报告的断言汇总补充进去；
    • 运行时立刻把被引网页存档。
    这就是上表"答案完整"一行里的第 2、3 条。这样得到的评分标准只对这一次运行有效，对一次性评测来说正合适。如果要每年重复用，就给评分标准加版本号和截止日期，每一轮预留专家重新裁决的时间。

10复核说明与未完成的核查

数字是怎么来的

  • 任务数、语言、领域、要点数、许可，都直接从 tasks_and_rubrics.jsonl 统计。
  • 出版方：按每题 blocked.urls 里的域名判断。15 篇只有 ResearchGate、PubMed 之类的镜像链接，没有计入出版方。
  • 文章类型：只按标题关键词判断，偏保守。标题没写 review 的文章也可能是综述。
  • 截止年份：在题目正文里找年份，不含屏蔽规则，取最大值。
  • 领域标签是否贴切：是我的判断。"标签继承自种子题"是推断。
  • 版本比对：三个提交版本逐题比较了 prompt、rubric、blocked、task 字段。

对之前对话中说法的更正

  • 对话里一度说"130 道题写明了时间范围"。那次统计把屏蔽规则里的年份也算进去了，只看题目正文是 116 道。

还没做的核查

  • 131 篇来源文章的被引百分位和撤稿情况。2026-10-28 试过 OpenAlex，它现在要求 API key，当天的免费额度已用完。可以改用 Crossref（撤稿信息已并入）重查。
  • 抽样追溯要点到一手来源，估计要点本身的错误率。这是"权威性"问题里最关键、也最缺的一环。
  • 用一个评委重跑论文的部分结果，检验可复现性。
  • 拿专家盲评排序和 DRB II 分数算相关性。这需要真人专家，与心得笔记里"人类专家盲测与 Agent 评测对比"的想法相关。
