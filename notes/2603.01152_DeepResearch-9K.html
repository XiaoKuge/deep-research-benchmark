0一分钟读懂

  • 它是什么：从 HotpotQA 等三个老牌多跳问答数据集里各抽 1,000 道题，让 DeepSeek-V3 改写成 L1 / L2 / L3 三个难度，共 9,000 道。再让通义的 Tongyi-DeepResearch-30B 全部做一遍，把它的搜索过程存下来当训练数据。
  • 主要用途是训练，顺带切出一个测试集：教师模型做错的 3,974 道里随机拿 1,774 道。
  • 论文的结论：
    • L3 很难，教师只答对 23.73%，"和 BrowseComp-Plus 一样难"；
    • 用它训练的 3B 小模型在测试集上 22.50%，超过 DeepSeek-V3 的 20.18%。
  • 我复核后发现的问题：
    • 出题脚本里唯一的"质检"是检查长度和格式，没有人、也没有程序核对过答案对不对、是否唯一；
    • L3 有 69.3% 是一段没有问号的叙述，根本没说要答什么，教师在这些题上错了 87%；
    • "难题集"里有 45.5% 是这种题；
    • L1 和 L2 的教师正确率几乎一样（72.5% 对 71.3%），难度分级没分开；
    • "和 BrowseComp-Plus 一样难"的依据 24.94%，和 BrowseComp-Plus 官方榜上这个模型的成绩（33%–68%，视检索器和工具设置而定）对不上，却恰好等于 BrowseComp-Plus 论文里另一个模型的成绩。
  • 适合的用法：当作"带完整搜索过程的合成训练数据"来研究，可以；当作评测基准，不建议。

1打个比方：一座谜题工厂

想象一座流水线工厂，原料是现成的简单问答题，产品是越来越难猜的谜题：

  1. 拿原料：从 HotpotQA、2WikiMultihopQA、MuSiQue 各抽 1,000 道题。这三个数据集都是 2018–2022 年发布的经典多跳问答。
  2. 挑一个起点：让 DeepSeek-V3 从每道题里抽出人名、地名、年份等"实体"，随机挑一个当起点（种子实体）。
  3. 接力：从起点出发，找相关的下一个实体，再下一个……
    • L1 只要起点的 3 个属性；
    • L2 走 A → B → C 两步；
    • L3 走 5–6 步的"接力赛"。
  4. 蒙面：把名字、日期、地点换成描述。
    • L1 只换同义词，比如"北京"换成"中国的首都"；
    • L2 去掉 1–2 个关键实体的专名；
    • L3 全部换成描述，写成一大段套着从句的叙述。
  5. 试做：让教师模型 Tongyi-DeepResearch-30B 联网做每一道题，把思考和搜索过程全部记下来。
论文图 1 的 L3 例题（原文英文，这里意译）

传说中在出埃及时与君王对峙的立法者，其经典里描述了一座刻下诫命的山。山脚下有一座古老的修道院堡垒，保存过现存最古老的圣经抄本之一；这部抄本在 19 世纪被一位欧洲学者发现，他的取得方式饱受争议。抄本的一部分如今藏于一座冷战时曾被分割的城市里的大型学术图书馆。这座图书馆叫什么？

答案：莱比锡大学图书馆。链条是：摩西 → 西奈山 → 圣凯瑟琳修道院 → 西奈抄本 → 蒂申多夫 → 莱比锡。

注意：这道"L3"在图里只用了 2 次工具调用就解出来了，而论文说 L3 至少要 15 次搜索。此外，题面说"冷战时曾被分割的城市"，而冷战时被分割的城市是柏林。莱比锡属于东德，本身没有被分割，图里的推理却说莱比锡"符合被分割的背景"。这道展示题本身就不太严谨。

29,000 道题怎么来

论文第 3 节描述了四步：抽种子、建链条、蒙面、"基于规则的质量保证"。2026-04-21，作者在 GitHub 上补上了出题脚本 data/create_data.py。对照脚本，可以看清每一步实际做了什么：

论文怎么说脚本里实际是什么
每个原始题生成三个难度是的。每个原始题依次生成 L1、L2、L3，编号为 {序号}_L1/L2/L3。3,000 × 3 = 9,000
L3 每一步都必须需要一次独立搜索，"没有任何一个维基页面包含两个以上相邻实体"只是写在给 DeepSeek-V3 的提示词里的一句要求，脚本没有检查
L3 至少需要 15 次搜索也只是提示词里的一句"难度目标"，没有检查
"基于规则的质量保证"函数 check_difficulty_fast：题目至少 40 个字符；L3 不能有换行、不能有 "(A)""Step 1""First," 这类列表标记。另外按题目文本的 MD5 去掉完全相同的题。就这些
"可核实的答案"答案是 DeepSeek-V3 生成题目时一并给出的 short_answer，生成温度 0.8。没有任何核对答案对错或是否唯一的步骤
"质量标准来自 BrowseComp-Plus 的高质量样例"脚本里看不到。论文说是"用 LLM 分析 BrowseComp-Plus 样例后总结出写作准则"

论文说全程只花了 200 美元的搜索 API 费。但同一段也写了还用了约 8,064 个 A100 GPU 小时。按每小时 1–2 美元算，是 8,000–16,000 美元。"低成本"只算了搜索费。

3训练集，还是考题？

标题叫 "Benchmark Dataset"，但实际上主要是训练数据。HuggingFace 上只有两个文件夹：

名字条数是什么
DeepResearch-9K9,000全部题目，每条带难度、教师的完整搜索过程、"最终答案"（即出题时的标准答案）
DeepResearch-Hard3,974上面那 9,000 里教师做错的部分（L1 826、L2 860、L3 2,288）。我核对过：3,974 条全部包含在 9K 里，答案字段完全相同

训练和测试是这样分的（来自 README，和论文一致）：

  • 训练集 7,226 条 = 教师做对的 5,026 条 + 从 Hard 里随机挑的 2,200 条；
  • 测试集 1,774 条 = Hard 里剩下的那些。

两个要点：

  • 测试集只由"教师做错的题"组成。README 说这是有意的，用来考"能不能纠正教师的错误"。
  • 那 2,200 条是哪些，没有公开。数据里没有题目编号，仓库里也没有切分脚本或随机种子，所以别人复现不出同一个测试集。另外 README 链接的独立 "DeepResearch-Hard" 数据集并不存在，Hard 只是同一个数据集里的一个文件夹。

4怎么判分

  • 准确率：DeepSeek-V3 当评委，判最终答案对不对。论文说评委提示词"在代码网站上"，但我在仓库里没找到。
  • 搜索次数：每条轨迹调用了几次搜索。用来说明难度分级有效。
  • 训练时的奖励：也是 DeepSeek-V3 给的。

5结果

  • 教师模型直接做全部 9,000 道：L1 72.47%，L2 71.33%，L3 23.73%，总体 55.84%。
  • "L3 和 BrowseComp-Plus 一样难"：论文说教师在 BrowseComp-Plus 上是 24.94%，和 L3 的 23.73% 接近（这个依据有问题，见 7.4）。
  • 训练实验（Qwen2.5-3B 和 Llama-3.2-3B，PPO 和 GRPO，直接强化学习和先模仿再强化学习两种）：
    • Qwen2.5-3B 直接强化学习约 12%，先模仿再强化学习超过 20%；
    • 最好的是 Llama-3.2-3B + PPO 直接强化学习，22.50%；
    • DeepSeek-V3 直接做是 20.18%。
  • 论文的结论：3B 小模型"超过了更大的 DeepSeek-V3"，达到"最先进水平"。

6名词小抄

多跳问答
答案要经过几步推理才能得到。比如"某电影导演的妻子是谁"：先找导演，再找妻子。
种子实体
造题的起点，比如一个人名或地名。
实体模糊化
把名字、日期、地点换成描述，让人没法直接搜。"北京"变成"中国的首都"，"维多利亚时代中期"代替具体年份。
教师模型
拿来示范的强模型，这里是 Tongyi-DeepResearch-30B。它的解题过程用来教小模型。
轨迹
模型解一道题的全过程：每一步想了什么、搜了什么、看到了什么。
先模仿再强化学习
先让小模型照着教师的轨迹学（监督微调，SFT），再用"答对给奖励"的方式继续练（强化学习，RL）。
直接强化学习
不先模仿，直接从基础模型开始用奖励练（Zero-RL）。
PPO / GRPO
两种常用的强化学习算法。
LLM 评委
让一个大模型来判答案对不对。

7弱在哪

关问的是表现为什么
① 判分答案判得准吗弱标准答案没人核对过，有 12% 的 L2 答案本身就是一段描述而不是名字；评委是出题的同一个模型（见 7.1、7.5）
② 比较分差可信吗弱测试集复现不出来；22.50% 对 20.18% 的差距和误差差不多大；只跑一次（见 7.6、7.7）
③ 推广难度分级、"和 BrowseComp-Plus 一样难"成立吗弱L1、L2 没分开；L3 的难主要来自没说要答什么；对照数字对不上（见 7.2–7.4）
④ 意义分高 = 深度研究能力强吗弱训练出的模型没在任何外部 benchmark 上测过；原料是网上流传多年的老题（见 7.7、7.8）

7.1 没有人核对过题目和答案

出题脚本的"质检"只看长度和格式（见第 2 节）。为了看看实际质量，我按固定随机种子从 9,000 道里抽了 25 道（L1 8 道、L2 8 道、L3 9 道），逐条人工阅读。下面是我的判断，没有逐条上网核实，一道题可能同时有几种问题：

问题类型条数例子
题目清楚、答案像是唯一的5比如那道"一座大坝威胁世界遗产，遗址里的统治者留下一件常被称为早期人权宣言的文物，文物现藏于哪座博物馆"
L3 没有问句，没说要答什么7 / 9整道题是一段以句号结尾的叙述，读完不知道该回答链条上的哪一个实体
答案字段是一段描述，不是名字4 / 8（L2）问"1857 年在波士顿创办、原名 The Atlantic Monthly 的杂志叫什么"，标准答案是"发表了马丁·路德·金《伯明翰狱中书简》的那本期刊"。问题里已经写出答案，答案反倒被蒙了面
题目有歧义、可能有多个正确答案3"那位前伊朗外长和某人谁出生得早"：伊朗有过很多位前外长。"《维奥莱特·诺齐埃尔》的主演哪年得了最佳女主角"：她得过不止一次
链条牵强或答案可疑4"一个源自意大利探险家名字的词"，答案却是 "American" 而不是 "America"
标为 L2 却一搜就有2题目把作者、年份、作品名几乎全写出来了

25 道里，我认为"题目清楚、答案唯一、明确问了什么"的只有 5 道左右。样本小，比例只能当参考。下面两节用全量数据验证其中最突出的两个问题。

7.2 "难题集"里装的多半是坏题

  • L3 没有问号的比例：3,000 道 L3 里有 2,079 道（69.3%）通篇没有问号，2,077 道以句号结尾。L3 的出题提示词只要求"写成一段密集的叙述"，没要求最后提问。
  • 教师在这些题上错得更多：没问号的 L3 错了 87.0%，有问号的 L3 错了 52.1%。
  • 它们在 Hard 子集里的占比：Hard 里的 2,288 道 L3，有 1,808 道没有问号，占整个 Hard（3,974 道）的 45.5%。
  • 测试集也一样：测试集是从 Hard 里随机抽的，所以测试集里大约也有 45% 是这种"没说要答什么"的题。

这暴露了一个常见陷阱："强模型做错的题"不等于"难题"。没人核对时，选出来的往往是题目本身有毛病的那些。论文把 Hard 说成"深度研究智能体能力的极限"，但至少有很大一部分是出题质量的极限。

另一个全量统计：L2 里有 362 道（12.1%）的标准答案本身是一段描述，比如"那位饰演芬尼克并在 LAMDA 受训的演员"。这违反了出题提示词自己的要求（"目标必须是具体、可核实的名字"）。

7.3 难度分级只分出了两档

  • 教师正确率：L1 72.47%，L2 71.33%，几乎一样。只有 L3 明显更难。
  • 只看教师做对的题，搜索次数的中位数是：L1 2 次，L2 2 次，L3 10 次。L1 和 L2 在解题过程上也没有区别。
  • "L1 严格限定 1–2 次搜索"：实际只有 44%（1,333 / 3,000）的 L1 轨迹在 2 次以内。
  • "L3 至少要 15 次搜索才能解出"：教师做对的 712 道 L3 里，有 460 道（65%）不到 15 次就解出了，231 道只用了 5 次以内。

所以"难度和搜索次数挂钩"更多是设计意图，数据并不支持。

7.4 "和 BrowseComp-Plus 一样难"的依据对不上

一个数字的核对
  • 论文说：Tongyi-DeepResearch-30B-A3B 在 BrowseComp-Plus 上 24.94%，接近它在 L3 上的 23.73%。
  • BrowseComp-Plus 官方排行榜上，这个模型有 6 条成绩，主列在 33.98% 到 68.07% 之间。用 BM25 检索是 33.98%（GPT-4.1 判分为 33.37%），用 Qwen3-Embed-8B 检索是 44.46%（GPT-4.1 判分为 44.10%），用原生工具是 36.87% 和 51.93%。
  • 24.94% 这个数，恰好出现在 BrowseComp-Plus 论文表 4：那是 gpt-oss-120B 低思考档 + Qwen3-Embed-8B 的准确率，不是 Tongyi 的。
  • 巧的是，同一行的召回率是 22.50%，正好等于本文最佳模型的准确率。这可能纯属巧合，我无法判断。

论文没给 Tongyi 在 BrowseComp-Plus 上用的检索器和设置，也没提供运行记录。合理的推断是，这个数字很可能抄错了行。即使没抄错，"一个模型在两套题上分数接近"也说明不了两套题一样难。何况本文的写作准则本身就是从 BrowseComp-Plus 样例里总结出来的。

7.5 同一个模型身兼数职

DeepSeek-V3 在这项工作里一共担任了六个角色：

  1. 从原始题里抽实体；
  2. 生成题目和标准答案；
  3. 把教师轨迹整理成"维基风格摘要"，作为训练时的检索语料；
  4. 训练时给奖励；
  5. 评测时当评委；
  6. 当被比较的对手（20.18%）。

出题人、阅卷人、对手是同一个模型，"小模型超过了 DeepSeek-V3"就很难解读。比如，评委和出题者对答案的理解天然一致；而它作为对手做自己出的题，表现却只有 20%。这本身也说明题目或答案有问题。

7.6 训练和测试分不干净

  • 测试题和训练题来自同一批 3,000 道原始题。同一道原始题的 L1、L2、L3 可能一部分在训练集、一部分在测试集。
  • 全量统计：有 298 个答案（不算 yes/no）同时出现在两个以上难度里；Hard 里有 307 道题，它的答案也是其他难度某道题的答案。这些题进测试集时，训练集里可能就有"同一个答案"的兄弟题。
  • 训练用的检索语料是 DeepSeek-V3 根据教师轨迹生成的摘要。论文没说是否排除了测试题的轨迹，评测时用的是这份语料还是真实网络，也没说清楚。这一条我没能核实。

7.7 "最先进"的说法超出了实验

  • 摘要说训练出的模型"在有挑战性的深度研究 benchmark 上达到最先进水平"。但实验里训练出的模型只在自己的测试集上测过，对手只有 DeepSeek-V3 一个。没有在 BrowseComp-Plus 或其他外部 benchmark 上测。
  • 测试集 1,774 道，准确率在 20% 左右时，误差约 ±1.9 个百分点（95% 置信区间，单个系统）。22.50% 对 20.18% 只差 2.3 个百分点，而且同时比较了 8 种训练配置、每种只跑一次。说"超过"证据不足。

7.8 原料是网上流传多年的老题

  • L1 基本是原题换个说法。数据里第一道 L1 是"1970 年电影《Move》的导演和 1963 年电影《Méditerranée》的导演是不是同一个国家的人"。教师在思考过程里直接写出了 2WikiMultihopQA 的原题措辞（"Are director of film Move (1970 Film) and …"），说明它很可能见过原题。
  • 433 道 L1（14.4%）的答案是 yes 或 no，瞎猜也有一半机会答对。
  • HotpotQA 2018 年、2WikiMultihopQA 2020 年、MuSiQue 2022 年就公开了，题目和答案早已大量进入模型的训练数据。

7.9 小问题

  • 9,000 道里有 4 对完全重复的题。
  • HuggingFace 数据集没有标许可证。论文本身是 CC BY-NC-ND 4.0，代码是 Apache-2.0。
  • README 里指向独立 "DeepResearch-Hard" 数据集的链接打不开。

8它做对了什么

  • 真的公开了全部数据和完整轨迹。12,974 行，每条带教师的思考和搜索过程。对研究"小模型怎么学搜索"很有用，本文的所有复核也是因此才做得了。
  • 补上了出题脚本。虽然暴露了质检的薄弱，但这种透明值得肯定。很多论文只给描述不给代码。
  • "用搜索次数衡量难度"的思路是对的。只是需要实测，而不是只写在提示词里。
  • 训练实验给出了小规模的有用对照。同样 3B 的规模下，"先模仿"对 Qwen 很关键，对 Llama 不是必需。
  • 没有利益冲突的迹象。作者有百度的人，但被测和被训练的模型里没有百度的模型。

10对"同一 Prompt、5 个 Agent"的启示

  1. "所有 Agent 都没答对"先怀疑标准答案。汇总 5 份报告时，如果专家清单里某一条 5 家全漏了，或者 5 家都给出了和清单不一样的说法，先回头核对清单本身，再扣 Agent 的分。DeepResearch-9K 的 Hard 子集就是反面教材：把"强模型做错"直接当成"题难"。
  2. Prompt 必须明确"要交什么"。69% 的 L3 题没说要答什么，教师在这些题上就大面积失分。写那道共享 Prompt 时，每个子问题都要写清楚期望的产出：一个名字、一张表，还是一个判断加理由。
  3. 出题、评委、选手不要是同一个模型。如果 5 个 Agent 里有某家的模型，评委就换成别家，或者用多家评委取多数。
  4. 难度要实测，不要只靠设计。如果给子问题标了难易，先用一两个 Agent 试跑，看实际的搜索次数和正确率是否真的分出了档次。
  5. 引用外部数字之前先核对原始出处。7.4 的那个 24.94% 就是例子。评测报告里引用的每一个"某模型在某榜单上多少分"，都应该链到可查的原始记录。
  6. 可以借它的轨迹格式。如果 5 个 Agent 是自己搭的、能导出搜索过程，"思考 → 工具调用 → 返回结果"这种格式便于统计搜索次数、打开网页次数，以及有没有回头重想。

11复核说明

  • 论文版本：arXiv 接口显示 v1 2026-03-01，v2 2026-06-20。本地 PDF 是 v2，SIGIR 2026 短文。
  • 数据：下载了 HuggingFace 上的两个 parquet 文件（DeepResearch-9K 9,000 行，DeepResearch-Hard 3,974 行），用 pyarrow 全量读取。以下都是全量统计：难度分布、Hard 与 9K 的包含关系、重复题、yes/no 答案、题目长度、教师搜索次数、没有问号的题、答案为描述的题、答案出现在题目里的题、跨难度共享答案。
  • 几个判别口径：
    • "没有问号"：题目文本里不含 "?"。
    • "答案是描述"：以 The / A / An 开头、超过 35 个字符、且含 that、who、whose、which 等从句词。这是启发式规则，会有少量误判。
    • "搜索次数"：数轨迹中 assistant 消息里 name 为 search 的 <tool_call>。
  • 抽样：用随机种子 20261028 抽了 25 道题，判断是人工阅读得出的，没有逐条联网核实。
  • 出题脚本：读的是 GitHub 上 2026-04-21 提交的 data/create_data.py，其中 MODEL_NAME 留空，论文说用的是 DeepSeek-V3。
  • BrowseComp-Plus 对照：
    • 排行榜数据：Tevatron/BrowseComp-Plus-results 的 agent_results.csv（2026-10-20 版），里面 Tongyi-DeepResearch-30B-A3B 有 6 条成绩；
    • 24.94% 的出处：BrowseComp-Plus 论文表 4。
  • 没做的核查：
    • 没查和 BrowseComp 原题的重叠：BrowseComp 是加密发布的，我没有解密；
    • 没查测试题的轨迹有没有进训练检索语料：语料没有公开；
    • 没有重跑任何模型。
