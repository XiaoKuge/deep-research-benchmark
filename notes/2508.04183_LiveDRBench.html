0一分钟读懂

  • 核心主张：深度研究的关键不是"写出一份长报告"，而是"在大量资料里把该找的断言找全、找对，并给出出处"。写报告只是最后一步的成文，可以另外评。
  • 怎么评：
    • 把 Agent 的输出变成一张断言清单，每条断言带着支撑它的子断言（比如出处论文）；
    • 对照标准答案算精确率（说出来的有多少是对的）和召回率（该说的说全了多少）；
    • 主断言错了记 0 分；主断言对了但出处全错，也记 0 分，这样防止"靠记忆蒙对答案"。
  • 怎么出题：把"给你一篇文章，找出里面的信息"倒过来，变成"给你这些信息，找出是哪篇文章、哪个东西"。共 100 道题、8 类，覆盖科研和公共事件。
  • 结果（2025 年中）：OpenAI DR 平均 F1 0.55，Perplexity DR 0.36，Gemini DR 0.26。
  • 问题：
    • 名字叫"Live"，但 14 个月没有加过一道新题；
    • 有 10 道题的标准答案以明文公开；
    • 有 10 道列举题没写截止时间，答案会随时间变；
    • 标准答案只按当时那几个系统的输出做过补充，对后来的新系统不公平；
    • 每类只有 3–20 道题，按类比较噪声很大。
  • 对你的场景：在读过的四篇里，这篇的评分方法最能直接拿来用。"断言 × 出处"的打分公式，加上"汇总所有 Agent 的输出、人工裁决后补进标准答案"，正好就是我们一开始讨论的"证据清单"方案。

1核心主张：研究 = 找断言

打个比方：写一篇综述，真正花时间的不是排版和成文，而是之前那张"发现清单"：查到了哪些事实，每条出自哪里。清单找全了、找对了，成文是相对容易的一步。清单错了漏了，文章写得再漂亮也没用。

论文把深度研究拆成两步：

  1. 发现断言：在资料里找出能回答问题的一条条信息，以及支撑它们的证据。这是本文要评的。
  2. 写成报告：把断言组织成文字。论文认为这是一个独立的"长文本生成"问题，可以单独评，本文不管。

什么样的问题算"深度研究"？论文给了两个条件，同时满足才算：

  • 搜索量大：要处理很多信息单元（大致是一个段落）。论文给的参考线是 20 个以上，至少搜 10 次。
  • 要动脑子：找、读、合并信息这三步里，至少有一步需要不简单的推理。参考线是"一个理想的专家用网络搜索也要花 10 分钟以上"。
论文给的例子
  • 是深度研究："由女性作者的小说改编、片长 80–95 分钟的奥斯卡获奖电影"。要翻很多片子，逐部核对条件。
  • 搜索量不够："这篇论文里用的材料有什么性质"。答案就在一篇文章里。
  • 推理量不够："NeurIPS 2024 录用论文列表"。列表一抓就有，不用推理。
  • 是不是深度研究还取决于资料库：如果某天网上出现一个页面，正好列出了全部答案，这道题就不再是深度研究了。

2怎么出题：把阅读题倒过来

论文管这叫"问题倒置"（problem inversion）：

原来的阅读题倒过来的深度研究题
给你什么一篇材料学论文一组测量数据：带隙 3.35 eV、结合能 60 meV、晶格常数 a = 0.325 nm、c = 0.521 nm……
要你做什么列出论文里这种材料的各项性质找出是哪种材料、出自哪篇论文，并摘出原文的表格和段落
难在哪读懂一篇长文不知道去哪找，要拿数据反复搜、反复比对

这个例子来自论文附录 A。原题出自 Google 的 CURIE 阅读理解数据集。倒过来之后，作者还会人工检查答案是否唯一。如果不唯一，就加条件，或者把其他同样正确的答案补进标准答案。

这套做法的好处：只要有新的论文、新的赛事，就能照同样的流程出新题。这就是名字里"Live"的由来（不过后面会说到，并没有真的更新过）。

4怎么判分：断言 × 出处

每道题都要求 Agent 输出一份 JSON 清单。清单里每一项是一条主断言（比如材料名），下面挂着子断言（比如出处论文的标题）。

一条断言的得分 = 主断言对不对（0 或 1）× 子断言里对的比例

精确率 = Agent 说出的各条断言得分之和 ÷ Agent 说了几条
召回率 = Agent 说出的各条断言得分之和 ÷ 标准答案有几条
例子：材料题为什么分数这么低
  • 主断言是"材料名"，子断言是"出处论文"。两样都对才得分。
  • OpenAI DR 单看论文标题，F1 有 0.735；单看材料名，F1 有 0.504；两样都要对，就只剩 0.314。
  • 设计用意：答对材料但编了一篇不存在的论文，也是 0 分。这样可以防止"靠记忆蒙对答案、却说不出出处"。
  • 标准模式：各条断言的得分取平均。
  • 严格模式：取最小值。只要有一条错或漏，整题就是 0 分。适合"必须一个不落地列全"的题。
  • 权重：公式允许给重要的断言加权，论文的实验里没有用。

谁来判对错：GPT-4o 逐项比对 Agent 的答案和标准答案。Gemini DR 不按要求输出 JSON，只给报告，作者就手工把它的断言抄出来。作者自己也人工判了一遍（附录表 11），三家的平均 F1 和 GPT-4o 判的几乎一样：0.556 / 0.361 / 0.261，对比 0.555 / 0.355 / 0.263。

标准答案的补充：出题时的标准答案可能不全。所以作者把所有被测系统给出的断言都人工判了一遍，判为正确的就补进标准答案，再用补充后的版本自动打分。这就是信息检索评测里的"汇总裁决"做法。

  • 三家都是"说得准、说不全"。精确率普遍高于召回率：说出来的大多是对的，但该找的没找全。
  • 按类差别很大。F1 从 0.02（Gemini DR 做材料题）到 0.72（OpenAI DR 做地理题）。最难的是材料题、识别 + 提取题和航空题，这几类不光要找到对象，还要从长文档的多个部分里提取细节。
  • 不带深度研究模式的模型很吃力。o4-mini、Gemini 2.5 Pro 等开着搜索、只给约 30 秒思考时间，材料题全部是 0 分。不过 o4-mini 在不少类别上和 Perplexity DR、Gemini DR 不相上下。
  • 搜索记录分析（只看新数据集这一类的 19 道题）：
    • OpenAI DR 分岔和回头重想的次数最多，分数也最高；
    • Perplexity DR 平均翻 40 多个来源，但很少回头，"广而浅"；
    • Gemini DR 收手太早，来源少、思考少。
    翻的来源多，不等于答得好。

6名词小抄

断言
能回答问题的一条信息，比如"这种材料是 X"。
子断言
支撑断言的信息，比如"出自论文 Y""论文发表在 Z 会议"。
精确率
Agent 说出来的断言里，有多少是对的。说 10 条、对 7 条，就是 70%。
召回率
标准答案里的断言，Agent 说中了多少。标准答案有 20 条、说中 7 条，就是 35%。
F1
精确率和召回率的调和平均。两者都高，F1 才高；只顾一头，F1 会被拉低。
问题倒置
把"读文章找信息"倒过来，变成"给信息找文章"。
汇总裁决
把所有被测系统的答案合在一起人工判，正确的补进标准答案。英文叫 pooling。
严格模式
有一条错或漏，整题就是 0 分。

7弱在哪

还是那四关：

关问的是表现为什么
① 判分每条断言判得准吗强标准答案是具体的名字、标题、数字，GPT-4o 判的和作者人工判的几乎一致
② 比较系统之间的分差可信吗中偏弱总共 100 道题，按类只有 3–20 道；每个系统只跑了一次；没有误差范围（见 7.1）
③ 推广换个时间、换个系统，标准答案还成立吗弱标准答案只按当时那几个系统的输出补充过；一半列举题没写截止时间；10% 的答案是明文（见 7.2–7.4）
④ 意义分数高 = 深度研究能力强吗中"找断言"确实是研究的核心，但"10 分钟""20 个信息单元"这两条定义从没实测过；而且按设计就不评报告（见 7.5、7.7）

7.1 题太少，按类比几乎就是看运气

例子
  • "新数据集 · 识别"只有 6 道题。OpenAI DR 的 F1 是 0.667，就是 6 道里对了 4 道。多对或少对一道，分数就要变 16.7 分。
  • "新数据集 · 同类检索"只有 3 道题，任何结论都靠不住。

论文没有给误差范围。每个系统只跑了一次，而且是在网页聊天界面里手工提交的。

7.2 名字叫"Live"，但没有 live 起来

  • HuggingFace 数据最后更新于 2025-08-08，只有 v1。GitHub 后来只修了几次代码，最后一次提交在 2025-10-16。14 个月里没有加过一道新题。
  • 更麻烦的是，有些题的答案本身会随时间变。20 道列举题里有 10 道没写截止时间：
    • 5 道问"某国 IMO 拿过至少几块奖牌的选手"。每年 7 月都有新一届 IMO，符合条件的人会变多。
    • 5 道问"烂番茄评分达到多少、片长在某个范围的电影"。新片会上线，评分也会变。
  • 标准答案停在 2025 年中。一个今天去查、正确列出了新选手或新电影的 Agent，反而会被判成"说错了"，精确率下降。
  • 另外 10 道写了时间范围（"截至 2025 年"的奥运题、限定月份的畅销书题），不受影响。

7.3 10% 的标准答案是明文

  • HuggingFace 上除了正式的 100 道题，还有一个 10 道题的"预览"子集。预览子集的标准答案没有加密，是明文。
  • 我逐题比对过：这 10 道题全部在正式的 100 道里。也就是说，从 2025-08-08 起，这个 benchmark 有 10% 的答案就以明文挂在网上，正式数据集的加密对它们不起作用。
  • 其余 90 道的答案是加密的，但解密方法和 BrowseComp 一样是公开的，只能防爬虫。题目本身也是明文的。

7.4 补充过的标准答案，只对当时那几个系统公平

"汇总裁决"本身是好做法，但补进标准答案的，只来自论文当时测过的那批系统。

例子
  • 假设一道地理题，确实还有第三篇论文也用到了全部指定数据集，但当时三家都没找到，它就不在标准答案里。
  • 后来的新系统找到了这第三篇，评分脚本只会拿它和标准答案比，结果判成"说错了"。
  • 反过来，当时三家找到的那些额外答案都已经被补了进去，它们自然占便宜。

这在信息检索评测里叫"汇总偏差"（pool bias）。论文和代码都没有给新系统提供"新答案送人工裁决"的通道。

7.5 定义里的两条门槛从没实测过

"理想专家要花 10 分钟以上""至少 20 个信息单元、10 次搜索"，这两条是论文对深度研究的定义，但都是"我们认为"（we posit）。论文没有请人实际做题计时，也没有统计每道题实际需要多少信息单元。所以不知道这 100 道题里，有多少真的跨过了自己定的门槛。

7.6 比较条件不统一

  • 三个 DR 产品当时没有 API，都是在网页聊天界面里手工提交的。遇到它们反问澄清问题时，统一回复"Go ahead"。
  • 作为对照的普通模型走 API，思考时间只给了约 30 秒（o4-mini 开"低"档，Gemini 2.5 Pro 只给 128 个思考 token）。"普通模型很吃力"有一部分是这个设置造成的。
  • Gemini DR 的断言是作者手工抄出来的，人工评测也是作者自己做的，没有外部标注员。
  • 利益关联：作者来自微软，论文提到 OpenAI DR 已集成进微软 Copilot，而 OpenAI DR 在这里排第一。当时其他 benchmark 上 OpenAI DR 也大多领先，所以不能据此说结果有偏，但这层关系值得知道。

7.7 按设计就不评报告

这是作者有意的取舍，不算缺陷，但要清楚它的边界：

  • LiveDRBench 只评"断言找得全不全、对不对"；
  • 报告写得清不清楚、分析得深不深、结论有没有用，都不在评测范围内。

README 里也写明了：不适合评估长报告的写作质量。

8它做对了什么

  • 把"找断言"和"写报告"分开。客观的部分（断言对不对、全不全）客观地评；主观的部分（写得好不好）留给别的方法。这比把两者混在一起打一个总分清楚得多。
  • 精确率和召回率都算。DRB II 只算召回，DailyReport 只算精确率，这篇两样都有。
  • 出处必须对。主断言对、出处全错也记 0 分，直接卡住"背答案"和"编出处"。
  • 严格模式和权重。可以按题目性质选择"列全才算"，也可以给重要断言加权。
  • 汇总裁决。承认标准答案可能不全，并用人工判过的被测系统输出来补。
  • 问题倒置是一个可复制的出题配方。有新论文、新赛事，就能照做。
  • 题型多样。从"找一根针"到"列出几十个"都有，不同题型对搜索和推理的要求不同。
  • 数据、代码、评测提示词全部公开，正式答案也加了密。

10对"同一 Prompt、5 个 Agent"的启示

这篇最值得借的是评分方法，不是题目。照它的思路，可以把 5 份报告的评测分成两层：

第一层：断言层，客观打分

  1. 把每份报告拆成断言清单：每条关键结论是一个主断言，它引用的来源和数据是子断言。
  2. 得分用"主断言对不对 × 子断言对的比例"。结论对、来源全错也是 0 分。
  3. 权重 w 用 DailyReport 的 P0 / P1 / P2：必须有的断言权重高，有更好的权重低。
  4. 标准答案 = 专家事先写的必答清单 + 5 个 Agent（各跑 3 次）全部断言的汇总裁决。人工判为正确的补进去，之后统一打分。
  5. 精确率和召回率都报。题目里要求"列全"的子问题，用严格模式。
  6. 吸取 7.4 的教训：如果以后要加第 6 个 Agent，它的新断言必须先送人工裁决，再打分。
  7. 吸取 7.2 的教训：Prompt 里写明截止日期，标准答案也按这个日期定。

第二层：报告层，主观比较

写得清不清楚、分析深不深、结论有没有用，按我们之前说的办法评：专家盲评，5 份两两比较或直接排序，评分人看不到第一层的分数。

两层分数分开报告，不要合成一个总分。
