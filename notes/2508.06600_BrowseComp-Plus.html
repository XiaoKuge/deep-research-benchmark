0一分钟读懂

  • 它做了什么：把 OpenAI 的 BrowseComp（一套很难的"网上找答案"题）从"上整个互联网去搜"，改成"在一个固定的 10 万份文档的资料库里搜"。资料库里有每道题必需的证据，也故意混进了大量看着相关、其实没用的干扰文档。
  • 好处：大家用同一个资料库、同一种搜索工具，就能分清分数是"搜索工具的功劳"还是"模型的功劳"。而且可以复现，成本也低。
  • 最重要的发现：
    • 同一个模型，只把搜索工具从老式的关键词搜索换成按意思搜索，准确率能翻一倍。
    • 把证据直接递给模型，GPT-4.1 能答对 93.5%；让它自己用关键词搜索去找，只答对 14.6%。所以难点在"找"，不在"想"。
  • 局限：
    • 考的是"大海捞针找一个短答案"，不是"写研究报告"。
    • 没测模型是不是早就背过答案。
    • 排行榜一年多就从 70% 涨到 95%，快考满分了。
    • 排行榜上的方案搜索设置各不相同，"同一套工具"的公平性正在流失。
  • 对你的场景：不能直接拿来评 5 个 Agent 的报告。但有三个做法可以借鉴：
    • 给所有 Agent 同一个搜索环境；
    • 把证据直接递给模型，看它能写成什么样（全知测试）；
    • 记录每个 Agent 翻到了多少关键证据。

1打个比方：换了一个考场

原来的 BrowseComp 像一场"开卷考试，可以上整个互联网查资料"。问题出在：

  • 每个考生用的搜索引擎不一样，有人用 Google，有人用 Bing，有人用自家的；
  • 网页每天都在变，今天能搜到的，明天可能就没了；
  • 考生考得好，说不清是"人聪明"还是"搜索引擎好"。

BrowseComp-Plus 把考场搬进了一间固定的图书馆：

原来的 BrowseCompBrowseComp-Plus
资料从哪来整个互联网，一直在变固定的 100,195 份文档，不会变
搜索工具各用各的，看不到内部统一提供，可以随意替换
能不能分清功劳不能，模型和搜索引擎绑在一起能：固定模型换搜索工具，或固定搜索工具换模型
能不能复现很难，网页会变能，同样的设置跑两次，结果一样
标准答案之外还有什么只有"问题 + 答案"还标好了每道题需要哪几份证据文档
成本要付商业搜索 API 的钱本地搜索，不用付搜索费

2一道题从头到尾（论文图 2 的例题）

1
题目

找出一篇 2023 年 6 月以前发表的研究论文的标题。这篇论文谈到了文化传统、科学过程和烹饪创新；它有三位作者，其中一位是西孟加拉邦的助理教授，另一位拥有博士学位。

标准答案：The Fundamentals of Bread Making: The Science of Bread（一篇讲面包制作科学的论文）。

这就是 BrowseComp 的典型风格：先想好一个冷门答案，再叠加一堆条件，让人很难直接搜到，但一旦找到又很容易核对。

2
拆成线索，每条线索配一份证据文档
  • 线索 1："2023 年 6 月前发表，谈到文化传统、科学过程、烹饪创新" → 论文在 ResearchGate 上的页面（日期 2023-05-17）。
  • 线索 2："一位作者是西孟加拉邦的助理教授" → Haldia 理工学院某位老师的介绍页。
  • 线索 3："另一位作者有博士学位" → 另一位作者的履历页（2009 年都柏林大学学院博士）。

这三份是证据文档，其中直接写着答案的那份（论文页面）叫金文档。

3
准备干扰文档

让 GPT-4o 把题目拆成几个小问题，比如"哪些研究论文提到了文化传统？""哪些研究论文提到了烹饪创新？"。每个小问题拿去 Google 搜，前 100 条结果都抓下来放进资料库。

这些文档看着很相关，其实帮不上忙，专门用来迷惑搜索。平均每道题配了 76 份干扰文档。

4
Agent 答题
  • Agent 只能用提供的搜索工具，在 10 万份文档里搜，可以搜很多次。
  • 每次搜索返回 5 条结果，每条只给看文档开头的 512 个 token（大约三四百个英文单词）。
  • 最后交三样东西：解释（引用文档编号）、简短答案、自报信心（0–100%）。
5
判分
  • GPT-4.1 对照标准答案判对错（论文的做法；排行榜后来改用 Qwen3-32B 判，见 6.5）。
  • 同时统计 Agent 一路上翻到了几份证据文档，以及它自报的信心准不准。

3这间图书馆是怎么建的

原版 BrowseComp 有 1,266 道题，最后只留下 830 道，筛掉了三分之一：

步骤剩下被筛掉的原因
原版 BrowseComp1,266只有问题和答案，没有出处
让 o3 联网找证据1,142124 道 o3 没给出证据（格式出错，或没把握不答）
抓取 o3 给的网页1,005137 道至少有一个网址抓不下来（有些网址是 o3 编出来的）
人工核验830
  • 175 道没通过。最常见的原因是证据不够，标注员补搜 20 分钟以上也没找齐。
  • 另有 42 道要用谷歌地图查距离；13 道答案不唯一或有歧义。
  • 还有一些原题本身就错了：例题里"写书的人"和"复出演戏的人"其实是同名的两个人。

人工核验由 14 名大学生标注员完成，用了 400 多小时。标注员要在文档里划出支撑每条线索的原文，再判断"这些证据合起来能不能把整道题答出来"。

用公开的标注文件（qrel_evidence.txt、qrel_golds.txt）复核：

  • 每道题的证据文档在 1–13 份之间，中位数 6 份，平均 6.1 份；
  • 金文档在 1–9 份之间，平均 2.9 份；有 270 道题只有 1 份金文档；
  • 每道题的金文档都包含在它的证据文档里，和论文的定义一致。

资料库总共 100,195 份文档，平均每份约 5,200 个英文单词。

4名词小抄

BM25
老式关键词搜索。题目里的词在文档里出现得越多、越罕见，排得越靠前。它不懂同义词。
向量检索
比如 Qwen3-Embedding、ReasonIR。把题目和文档都变成表示"意思"的一串数字，按意思接近程度排序。它能认出"助理教授"和 "Assistant Professor" 是一回事。
证据文档
回答这道题必需的文档，每条线索至少一份。
金文档
证据文档里直接含有最终答案的那几份。
干扰文档
和题目沾边、但帮不上忙的文档，专门用来迷惑搜索（英文叫 hard negative）。
准确率
最终答案答对的比例。
召回率
Agent 整个过程中翻到的证据文档，占全部证据文档的比例。比如一道题有 6 份证据，Agent 翻到了 3 份，召回率就是 50%。
Recall@5
只看搜索工具排出的前 5 条结果，里面有多少证据文档。
nDCG@10
前 10 条结果的综合质量分：相关的排得越靠前，分越高。
校准误差
模型自报的信心和实际正确率差多少。说"90% 有把握"的题，实际也应该对九成左右；如果只对一半，就叫校准差。
全知测试
英文叫 oracle。不让模型自己搜，直接把全部证据文档递给它，看它能不能答对。用来分别量出"找"和"想"的上限。

5它发现了什么

发现 1：只换搜索工具，准确率能翻一倍

模型用 BM25用 Qwen3-Embed-8B变化
Claude Sonnet 414.3%36.8%翻了一倍多
Claude Opus 415.5%36.1%翻了一倍多
GPT-4.114.6%35.4%翻了一倍多
o349.3%63.5%+14 个百分点
GPT-555.9%70.1%+14 个百分点

换句话说，过去在"上网搜"的 benchmark 上看到的模型差距，有一部分其实是搜索工具的差距。

发现 2：搜索工具好，还能省事、省钱

换成更好的搜索工具后，大多数模型每道题少搜 1–3 次，总花费也下降了：

  • GPT-5 跑完 830 道题：400 美元降到 361 美元；
  • o3：836 美元降到 741 美元；
  • Opus 4：2,044 美元降到 1,842 美元。

道理很简单：前几次就搜到了有用的东西，就不用反复换词再搜。

发现 3：难点在"找"，不在"想"

全知测试
  • GPT-4.1 自己用 BM25 搜：答对 14.6%。
  • 把全部证据文档直接给它：答对 93.5%。剩下 6.5% 的错题，人工逐题看过，都能从证据里推出答案，是模型自己推理错了。
  • 开源的 Qwen3-32B：自己搜 10.4%，直接给证据 83.3%。

这同时说明两件事：

  • 资料库本身是够用的，题目确实能从里面的文档答出来；
  • 开源模型和闭源模型"读懂资料"的能力差得不多，差距主要在"会不会搜"。

发现 4：开源模型的短板是"不爱搜"

提示词里明确要求使用搜索工具，Qwen3-32B 平均每道题却只搜 0.9 次，Search-R1 只搜 1.7 次。GPT-5 和 o3 每道题要搜 20 多次。搜得少，自然找不到。

发现 5：让模型多想一想，它就会多搜几次，也答得更好

gpt-oss-20B 有低 / 中 / 高三档"思考力度"。搭配 Qwen3-Embed-8B：

  • 低档：每题搜 1.9 次，答对 13.4%；
  • 高档：每题搜 23.9 次，答对 34.6%。

代价是更慢、更贵。

发现 6：只看开头 512 个 token 不够

给 GPT-4.1 加一个"打开全文"的工具后，准确率从 35.4% 涨到 43.6%，平均每题只多打开 1.85 份全文。

原因是：只有 86.5% 的题，答案出现在至少一份金文档的前 512 个 token 里。剩下的题，只看开头是看不到答案的。

发现 7：单独考搜索工具，最好的也很弱

直接拿整道题当搜索词：

  • Qwen3-Embed-8B 排出的前 5 条结果里，只有 14.5% 的证据文档；
  • BM25 只有 1.2%。

这类叠了一堆条件的题，用一句话一次搜不到，必须拆开来多轮搜。

发现 8：很多模型"自信过头"

GPT-4.1 + BM25 只答对 14.6%，但校准误差高达 69%。意思是它自报的信心远高于实际正确率，常常"说很有把握，其实答错了"。

GPT-5 + Qwen3-Embed-8B 的校准误差只有 9%，信心和实际表现基本对得上。

6弱在哪

从"分数高"推到"这个 Agent 研究能力强"，要过四关：

关问的是表现为什么
① 判分答对答错判得准吗强答案是短短一个标题、人名或数字，对照着判，很少有争议
② 比较两个系统的分差可信吗中资料库和工具固定，可以复现。但 830 道题的误差约 ±3 个百分点，而论文不给误差范围（见 6.7）
③ 推广换成真实互联网，排名还一样吗中偏弱资料库只有 10 万份，干扰文档的来源单一；"扩大资料库后结论不变"只在最弱的两个模型上验证过（见 6.3）
④ 意义分数高 = 研究能力强吗弱考的是找一个短答案，不考写报告；也没排除"背过答案"（见 6.1、6.4）

6.1 考的是"大海捞针"，不是"写研究报告"

  • BrowseComp 的题是倒着出的：先想好一个冷门答案，再叠条件。真实用户很少会这样提问。
  • 最后只判一个短答案对不对。综合多方信息、处理互相矛盾的说法、判断来源可不可信、写清楚结论，这些都不在考查范围内。
  • 所以它适合测"搜索 + 推理"这一项基本功，不能代替对研究报告的评测。

6.2 830 道题是筛过的，筛子是 o3

  • 每道题的证据链，最初都是 o3 在网上找的。o3 找不到证据的题（124 道）、给的网址抓不下来的题（137 道），直接被筛掉了。
  • 剩下的题，偏向"o3 这类系统找得到证据"的那部分。而 o3 和同家族的 GPT-5 恰好是榜上成绩最好的。
  • 资料库里放的主要是 o3 那条证据链上的网页。如果某个 Agent 本来会走另一条同样正确的路（从别的网页推出答案），在这间图书馆里就走不通，因为那些网页不在库里。标注员可以补搜文档，这一点缓解了一部分问题。
  • 这是一个值得注意的偏向风险，论文没有分析。我也没法证明它确实影响了排名。

6.3 图书馆小，"扩大资料库"的检验只做了一半

  • 真实互联网有几十亿个网页，这里只有 10 万份。干扰文档全部来自"GPT-4o 拆出小问题 → Google 前 100 条"，长得都差不多。
  • 论文把 FineWeb-edu 的文档混进来，资料库扩大到 977 万份，约为原来的 100 倍。论文自己写的是"约 10 倍"，但按它给的数字算是 100 倍左右。它的结论是"结论不变，10 万份够用"。
  • 但在端到端准确率上，这个检验只用了 Search-R1 和 Qwen3-32B。这两个模型本来只有 3–10% 的准确率，几乎在地板上，变化本来就小。论文没有在 GPT-5、o3 这些强模型上检验。

6.4 没测"是不是早就背过答案"

  • 原版 BrowseComp 2025 年 4 月就公开了。加密只能防爬虫，解密方法本身是公开的，每个跑评测的人都要先解密。题目和答案迟早会以各种形式进入训练数据。
  • LiveBrowseComp 测过：在原版 BrowseComp 上，Agent 不联网最多能答对 44.5%。
  • 固定资料库只控制了"搜"这一侧，管不住模型的记忆。一个背过答案的模型，可以直接拿答案去搜，找几份文档来引用就行。
  • 论文没有报告"不给搜索工具时能答对多少"这个基线。这是最便宜、也最该补的一项检验。

6.5 排行榜上的"公平"在流失

排行榜目前有 87 条成绩，52 条是作者团队自己跑的，其余是各家把结果文件发邮件提交的。

  • 设置不再统一。论文的标准设置是"每次 5 条结果、每条看 512 个 token"。排行榜上的方案五花八门：一次返回 200 条、可以在代码环境里随意调用、最多 8 个 Agent 协作。这又回到了"分不清是谁的功劳"的老问题。
  • 例子：第一名 95.18% 是 AI21 的方案：GPT-5 加混合检索，最多 8 个 Agent 协作，平均每题搜 209 次。论文里 GPT-5 每题只搜 22 次左右。两个数字放在同一张榜上，比的已经不是同一件事。
  • 判分模型换了。论文用 GPT-4.1 判分，仓库现在默认用开源的 Qwen3-32B。排行榜的主列按仓库说明应该就是 Qwen3-32B 判的，另有一列"GPT-4.1 判分"。47 条两列都有的成绩里，主列平均高 0.7 个百分点。差得不多，但新旧成绩并不完全可比。

6.6 快考满分了

  • 2025 年 8 月论文发布时，最高是 GPT-5 的 70.1%。到 2026 年 4 月，已经有 95.18%。现在 80% 以上的有 10 条，90% 以上的有 4 条。
  • 作为参照：把全部证据直接递给 GPT-4.1，也只答对 93.5%。头部方案已经超过了这个"全知"参照线。
  • 830 道题全部公开，没有藏起来的测试集。各家可以反复在同一套题上调方案，分数越调越高，但不一定代表真实能力提高了同样多。
  • 对最强的系统来说，这套题的区分力已经快用完了。拿它比较搜索工具（固定一个中等模型，只换检索器）还有用。

6.7 误差：差 3 个百分点以内基本分不出来

830 道题的准确率，自带约 ±3 个百分点的误差（95% 置信区间，单个系统）。论文的表格没有给误差范围，每个设置也只跑了一次。

例子

同样用 Qwen3-Embed-8B，Opus 4 是 36.1%，Sonnet 4 是 36.8%。0.7 个百分点的差距远小于误差，不能说 Sonnet 4 更强。在同一批题上做配对比较能把误差压小一些，但论文没有做。

6.8 人工标注的质量只交代了一句

  • 14 名大学生标注员，交叉抽查的一致率"平均 80% 以上"。也就是说，大约每 5 个判断里可能有 1 个两人意见不同。
  • 论文没有给出更细的一致性指标，也没说分歧是怎么处理的。

7它做对了什么

  • 控制变量。固定资料库、统一搜索接口，第一次能干净地回答"这个提升是搜索工具带来的，还是模型带来的"。
  • 可以复现，而且便宜。不依赖会变的网页和收费的搜索 API。GPT-5 跑完全部题目约 360 美元。
  • 标好了每道题的证据文档。可以按信息检索领域的标准方法（TREC 那一套）单独考搜索工具。这对 BrowseComp 来说是第一次。
  • 全知测试设计得好。一个实验就把"找"和"想"拆开了，结论清楚。
  • 诚实地交代了筛掉了什么、为什么筛（附录 C），还举了原题出错的例子。
  • 防泄漏。题目加密发布，附 canary 标记。
  • 全部公开：数据、代码、排行榜，以及每个设置的 API 花费（附录表 8）。

8对"同一 Prompt、5 个 Agent"的启示

BrowseComp-Plus 不评研究报告，所以不能拿来当主考。但它的几个做法可以直接借：

  1. 给 5 个 Agent 同一个搜索环境。
    • 如果 5 个 Agent 是自己搭的、可以换搜索工具：给它们同一个搜索 API、同样的返回条数、同样的读全文规则。这样分数差距才能归到 Agent 身上。
    • 如果是商业产品、换不了：至少把每家引用和访问过的网页全部存档，事后核验都对照存档。
  2. 做一次全知测试。汇总 5 份报告里核验为真的证据，交给同一个模型去写报告，看看"资料齐全时能写多好"。拿每个 Agent 的报告和它对比，就能看出差距是"没找到"还是"没写好"。
  3. 记录证据召回。如果能拿到搜索记录，统计每个 Agent 翻到了汇总证据里的多少份关键证据。这是比最终报告更早、更客观的过程指标。
  4. 让 Agent 给关键结论标信心。事后检查"说很有把握的结论"是不是真的更常对。这就是校准，能看出哪个 Agent 会"自信地说错"。
  5. 把设置写死、写进预登记。工具、返回条数、能不能读全文、时间和花费上限，5 家要一样，并且记录下来。排行榜的教训是：设置一不统一，比的就是配置而不是 Agent。
  6. 先测"背没背过"。每个 Agent 先在关掉搜索的情况下答一遍核心问题。答得出来的部分，后面的搜索得分就要打折扣看。
