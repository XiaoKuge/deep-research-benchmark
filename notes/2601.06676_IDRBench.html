0一分钟读懂

  • 它问的问题：深度研究一跑就是几十分钟，开头理解偏了，后面全白费。如果 Agent 能在规划、研究、写作三个阶段停下来问用户一句，最后的报告会不会更贴合用户想要的？代价有多大？
  • 怎么测：
    • 同一个模型、同一套流程，各跑两遍：一遍从头到尾自己做，一遍允许中途最多问 5 次。
    • "用户"由 GPT-5.1 扮演。它手里有一份目标报告，按报告的意思回答问题，但被要求不直接透露内容。
    • 比较两遍的报告分别和目标报告有多像。
  • 结论：7 个模型全都变好了，平均提升 6.39 分。但 700 个"模型 × 题"组合里，有 19.9% 反而变差。
  • 需要打折扣的地方：
    • 提升里有多少来自"问到了目标报告里的信息"，有多少来自"多停下来想了一轮"，论文没有分开测。缺一个"用户只回答'按你的判断来'"的对照组。
    • 同一配置在论文的三张表里出现了三次，分数相差 0.9–1.8 分（我对照出来的）。而交互模式下前三名之间只差 0.6–1.5 分。
    • 交互模式的排名和自主模式几乎一样（相关系数 0.89），"交互能力是一个独立维度"的说法证据不足。
    • 评分只量"像不像目标报告"，不管内容对不对。目标报告很可能是 Gemini-2.5-Pro Deep Research 写的，而 Gemini-2.5-Pro 本身也是被测模型。
    • 没有公开代码和数据。
  • 对你的场景：5 个 Agent 是单轮、同一个 Prompt，不需要测交互能力。但这篇提醒了一个公平性问题：有的 Agent 开跑前会反问澄清，有的不会。能得到回答，平均要多出 6 分以上的"贴合度"，所以必须事先定好统一的处理规则。

1打个比方：装修师傅该不该问

你跟设计师说"帮我把客厅改得现代一点"，接下来有两种设计师：

  • 闷头型：三周后直接交方案。风格可能完全不是你想的那种"现代"。
  • 会问型：出草图时问一句"偏极简还是偏工业风？"，选材时问一句"预算上限多少？"，收尾时问一句"要不要留书架？"。更可能做出你要的样子，但问太多你也会烦。

IDRBench 想测的就是这种"会问"的能力，拆成四件事：

  1. 要不要问：这时候停下来问值不值得；
  2. 什么时候问：规划阶段、研究中途，还是写之前；
  3. 问什么：范围、重点、受众，还是细节；
  4. 问完怎么用：回答有没有真的改变后面的研究和写作。

同时还要记下"打扰成本"：问了几次、每次多少字。

2题目从哪来

  • 100 道题来自初代 DeepResearch Bench，覆盖 22 个领域，中英文各 50 道。每道题原本配有一份报告。
  • 先把题目变模糊：原题写得太详细（最长约 800 个 token），几乎没什么可问的。作者用一个 LLM 把每道题删掉 10%–90% 的内容，只保留主题和核心目标。删完的题目仍然以原来那份报告为"目标"。论文没说用的是哪个 LLM。
  • 压缩后的题目经过人工检查：和原题一致、读着自然、内容安全。
例子：论文附录表 6，第 54 题
  • 原题：机器学习在资产配置中应用很广。均值-方差、Black-Litterman 这类经典模型，以及新兴的深度学习模型，各有长处也各有局限：均值-方差假设收益服从正态分布，Black-Litterman 依赖主观观点，深度学习可解释性差。这些模型在风险度量、收益预测、资产配置上的核心差异是什么？能否结合各自优点，建立更通用的框架？
  • 压缩后：传统模型和机器学习模型在资产配置的风险度量和收益预测上，主要有什么区别？能否把各自优点结合成更有效的框架？
  • 删掉了什么：具体的模型名字，以及每个模型的局限。

"目标报告"从哪来：论文只说用的是"DeepResearch Bench 的问题-报告对"。初代 DeepResearch Bench 论文写明，它的参考报告选自 2025 年 4 月由 Gemini-2.5-Pro Deep Research 生成的文章（我查了原文）。所以 IDRBench 的目标报告很可能就是这批 Gemini 写的报告。这一点是推断，论文没有说明。

论文也没有报告两件事：压缩比例是怎么分布的，以及不同压缩程度下交互各带来多少提升。

3交互怎么实现："用户"是谁

统一的研究流程

所有模型都放进同一套开源流程（LangChain 的 Open Deep Research），里面有 6 个角色：

  • 原有 4 个：规划者（把问题写成研究简报）、主管（拆分子任务）、研究员（去搜索）、写作者（写报告）；
  • 新加 2 个：评估者（判断现在值不值得停下来问）、提问者（写出一两个具体问题）。

被测模型一个人包揽全部 6 个角色，零碎的杂活由 GPT-4.1-nano 做。搜索用 Tavily，主管最多 6 轮，每个研究员最多调用 5 次工具。

提问预算

阶段最多问几次典型问题
规划1你要的范围、重点、受众是什么
研究循环3查到这些了，要往哪个方向深挖
写作1报告侧重哪部分、用什么结构

每次问一到两个问题。所有模型的预算都一样。

"用户"不是真人

  • 主实验里，"用户"由 GPT-5.1 扮演。论文称之为"受控反馈"，提示词里叫"用户模拟器"。
  • 它手里拿着目标报告，作为别人看不到的背景。提示词要求它只给贴着问题、高层次的回答，不提报告本身，也不添加原本没有的要求。
  • 所有被测模型面对的是同一个"用户"（同一个模型、同一套提示词）。但每个模型问的问题不同，得到的回答也就不同。

会不会泄露答案

  • 字面检查：回答和目标报告的 ROUGE-L F1 平均只有 0.0211，最长的相同片段平均 4.62 个词，几乎没有照抄。
  • 语义检查：用 GPT-5.5 把全部 1,816 条回答分成两类。1,778 条（97.91%）是"偏好澄清"，比如范围、重点、受众、格式；38 条（2.09%）含"具体内容"，比如结论、排名、数字。这个分类没有人工复核。
  • 我的保留意见："偏好澄清"恰恰就是评分指标在量的东西，见 7.1。

真人对照（只有一个小实验）

2 位真人在 10 道题上回答了 Gemini-2.5-Pro 提出的问题，回答前没看过 GPT-5.1 的回答。结果：

  • 不让问（自主）：71.25 分；
  • 真人回答：76.76 分；
  • GPT-5.1 扮演的用户回答：78.42 分。

两位真人是谁、手里有没有目标报告，论文都没说。

4怎么判分

报告对齐：五项指标，全是"和目标报告有多像"

指标怎么算
报告相似度用 Qwen3-Embedding-0.6B 把两篇整报告各变成一串数字（向量），算夹角余弦，再换算到 0–100。换算方式是 (1 + cos) / 2，所以两篇毫不相干的报告也有 50 分左右，实际分数都挤在 76–89 之间
句子 F1把两篇报告切成句子、段落或 300 token 的片段，两个单元的向量相似度 ≥ 0.8 就算"对上"。召回 = 目标报告的单元里，有多少在生成报告里找得到对应；精确 = 反过来算。F1 是两者的调和平均
段落 F1
片段 F1
要点覆盖分（LLM-ACS）从原始的详细题目里抽出 8–20 个要点。GPT-4.1 给目标报告和生成报告分别打 0–5 分的覆盖度，取"生成 ÷ 目标"的比值，封顶为 1，再对所有要点求平均

"平均对齐分"是这五项的简单平均。论文自己也承认，这只是一个描述性的均值，不代表用户真正的效用。

交互成本

记录每个阶段问了几次，以及每次问题和回答各多少 token（只统计英文题，避免中英文分词差异）。另外报告每份报告的 API 费用。

不评什么：论文附录 C 写明，不评事实对不对、引用可不可靠、来源质量如何。

6名词小抄

自主模式
不许问，从头到尾自己做完。
交互模式
允许在规划、研究、写作三个阶段问用户，总共最多 5 次。
受控反馈 / 模拟用户
用一个 LLM（主实验里是 GPT-5.1）扮演用户，按统一规则回答问题。
目标报告
每道题配的一份报告，代表"用户心里想要的样子"，评分时拿它当参照。
题目压缩
用 LLM 把详细的原题删短、变模糊，让 Agent 有东西可问。
余弦相似度
把两段文字各变成一串数字，看它们"方向"有多接近。越接近，意思越像。
F1
精确和召回的调和平均。两头都高，F1 才高。
偏好澄清 / 具体内容泄露
回答是在说"你要什么"（范围、重点），还是直接说了"答案是什么"（结论、数字）。
bootstrap
从 100 道题里有放回地反复抽样、重算，看结果会在多大范围内晃动。
A/A 对照
同一个配置原样跑两遍，看分数自己会变多少，以此估计"噪声"有多大。
空回答对照
让用户对每个问题都只回"按你的判断来"。用来分清提升是来自"拿到了信息"，还是来自"多停下来想了一轮"。

7弱在哪

还是那四关：

关问的是表现为什么
① 判分"像不像目标报告"量得准吗中向量相似度和 0.8 阈值是机械规则，可以复现。但分数挤在一起（相似度在 76–89 之间）。要点覆盖分靠 GPT-4.1 打，没有人工核对
② 比较交互前后、模型之间的分差可信吗中偏弱每个配置只跑一次。论文三张表里，同一配置的分数相差 0.9–1.8 分（7.2）。bootstrap 只算了题目抽样的误差
③ 归因提升真是因为"问得好"吗弱没有空回答对照组。"用户"手里有目标报告，它回答的"偏好"正是指标在量的东西（7.1）
④ 意义分数高 = 真实用户更满意吗弱只量和一份报告像不像，不管对不对；真人对照只有 2 人、10 道题；目标报告很可能是 Gemini 写的（7.4、7.5）

7.1 是"问到了答案"，还是"问得好"？

"用户"手里拿着目标报告。它按要求只回答"偏好"，但这些偏好，恰好能把题目压缩时删掉的内容补回来。

设想的例子（基于附录第 54 题，不是论文里的真实对话）
  • 压缩后的题目已经没有 Black-Litterman 这个词了。
  • Agent 在规划阶段问："您最关心哪些模型的对比？"
  • "用户"看着目标报告回答："传统的均值-方差和 Black-Litterman，还有深度学习，重点讲各自的局限。"
  • 按论文的分类，这是"偏好澄清"，不算泄露。但要点覆盖分的那些要点，正是从原始详细题目里抽出来的。这一句话，把被删掉的几个要点全补了回来。
  • 所以"交互提升"测的，很大程度上是能不能把题目里被删掉的信息问回来。这本身是一种有用的能力，但提升多少和压缩比例绑在一起：删了 90% 的题，能补回来的多；删了 10% 的题，能补的少。论文没有按压缩比例拆开来报告。
  • 我算了提升和自主得分的 Spearman 相关：−0.82。离目标越远，补回来的越多。论文把这解释为"余地更大"，和上面的理解一致。
  • 缺一个空回答对照：问的次数和流程都不变，只是"用户"每次都回"按你的判断来"。只有这样，才能分清提升来自"拿到了信息"，还是来自"多停下来想了一轮、多跑了几步"。
  • 后一种可能是真实存在的：交互模式下 Claude 每份报告要多花 1.23 美元，说明多了不少调用。

7.2 同一配置，换一张表就差 1–2 分

论文在同一个 30 题子集上做了三个附加实验：换用户模型、压缩用户背景、换提问时机。三个实验里都有一组"默认配置"：GPT-5.1 当用户，给完整背景，三个阶段都能问。同一个配置，三张表给出的分数却不一样：

Gemini-2.5-Pro—79.2978.390.90

最合理的解释是这几组是分别跑的，差异来自重跑本身的波动。论文没有说明，这是我的推断。由此带来三个后果：

  • 前三名分不出高下。交互模式下 Claude 80.47、Gemini 79.89、GPT 78.97，彼此只差 0.6–1.5 分，落在重跑波动的范围内。"Claude 交互得分最高"这个结论靠不住。
  • "差不多"的结论成立，但检测力有限。换用户模型差 0.2–1.1 分、压缩背景差 0.1–1.2 分，都在噪声以内，所以"没有影响"的结论成立。但同样的噪声也意味着，1–2 分以内的真实影响根本检测不出来。
  • "变差 19.9%"分不清真假。单道题重跑的波动，只会比 30 题平均更大。所以 139 个"变差"里有多少是真变差、多少只是噪声，无法判断。需要做一次 A/A 对照：同一个模型在自主模式下原样跑两遍，看单题分数自己会变多少。

7.3 "交互能力是独立的一维"，证据不足

  • 论文结论说，交互能力"不能从自主表现推断出来"。
  • 但我算了交互模式排名和自主模式排名的 Spearman 相关，是 0.89。后四名（DeepSeek、Grok、Qwen、Llama）的顺序完全没变；变的只有前三名的内部次序，而前三名的差距在重跑噪声以内。
  • "Llama 提升最大"，主要是因为它起点最低（54.81）。交互之后它仍然是最后一名（65.78）。

7.4 只量"像不像"，而目标报告很可能是 Gemini 写的

  • 五项指标全是"和一份目标报告比相似度"。论文自己也承认，这份报告只是"多种合理结果中的一种"。一份写得更好、但和目标不一样的报告，反而会被扣分。
  • 目标报告的来源（推断）：初代 DeepResearch Bench 的参考报告是 Gemini-2.5-Pro Deep Research 生成的，而 Gemini-2.5-Pro 正是 IDRBench 的被测模型之一。
    • 可能的迹象：自主模式下，Gemini 的段落 F1 是 76.62，明显高于其他模型（61.03–73.65）。
    • 但它的句子 F1（38.36）并不突出，所以不能断定确实有偏向。只能说存在风险，论文没有讨论。
  • 评分环节里 OpenAI 模型身兼数职：GPT-4.1 打要点覆盖分，GPT-5.1 扮演用户，GPT-5.5 做泄露分类，而 GPT-5.1 本身也是被测模型。
    • 换用户模型的实验（表 8）显示，GPT-5.1 由自家模型扮演用户时并没有占便宜：76.96，对比 77.15 和 77.11。这一点论文做得好。
    • 但 GPT-4.1 当覆盖分评委这件事，没有做同样的检验。

7.5 模拟用户比真人"更好说话"

  • 真人对照只有 2 个人、10 道题、1 个模型（Gemini），两人的身份不明。
  • GPT-5.1 扮演用户带来的提升是 +7.17（71.25 → 78.42），真人带来的是 +5.51（→ 76.76）。模拟用户的效果比真人高出约 30%，可能是因为它答得更全、更贴近目标报告。
  • 所以主表里的交互提升，大概率高估了真实用户场景下的效果。

7.6 测的是模型，不是 Deep Research 产品

  • 7 个模型都放在同一套 LangChain 流程里跑，搜索轮数有上限。OpenAI DR、Gemini DR 这类成品不在测试范围内。
  • 被测模型偏旧：2026 年 9 月的 v3 用的仍是 GPT-5.1、Claude-Sonnet-4.5、Gemini-2.5-Pro。论文的解释是 Gemini 3 系列和这套流程配合不稳定。

7.7 没有代码和数据

  • 论文没给任何链接，HuggingFace 的论文页上也没有关联代码或项目页。
  • GitHub 上搜 IDRBench，只有一个无关项目。HuggingFace 上的 IDRBench/IDRBench 是另一个同名 benchmark（识别跨学科研究论文，2025-05 建立）。
  • 压缩后的 100 道题、模拟用户的回答、各模型的报告，都拿不到。题目压缩用的是哪个 LLM、压缩比例怎么分布，论文也没写。

8它做对了什么

  • 问了一个真问题。长流程里，开头的理解偏差会一路放大。"会不会停下来问"是现有 benchmark 都没测的。
  • 对照设计干净。同一个模型、同一套流程、同样的预算，只改"能不能问"这一个变量。唯一的缺口是没有空回答组。
  • 把"问"拆得很细。分成要不要问、何时问、问什么、怎么用，并报告每个阶段的次数、token 和每份报告的 API 费用，成本很透明。
  • 不只报平均。把"变差"的比例（19.9%）也报了出来，提醒大家"能问"不等于"会问"。
  • 做了一圈自查：换用户模型、压缩用户背景、字面和语义两种泄露检查、真人对照、按题 bootstrap、逐项去掉指标看稳不稳。每项规模都小，但方向是对的。
  • 诚实写明了边界：不评事实和引用；平均分只是描述性的；bootstrap 不包含重跑误差。

10对"同一 Prompt、5 个 Agent"的启示

你的场景是单轮评测，不需要把"交互能力"当成一个评分维度。但这篇提醒了四件事：

  1. 反问澄清要统一处理，写进预登记。不少 DR 产品开跑前会先反问。IDRBench 显示，能得到回答，平均要多出 6 分以上的"贴合度"。如果有的 Agent 反问了、你也答了，有的 Agent 没反问，比较就不公平。两种做法二选一：
    • 统一不给信息：任何反问都回同一句"请按你的判断进行"（LiveDRBench 的做法）。
    • 统一给信息：事先写好一份"用户意图说明"（对象、范围、重点、受众），任何反问都只从这份说明里取答案，并记录每家问了什么、得到了什么。
    推荐第一种，同时把 Prompt 写完整（总问题 + 子问题 + 截止日期 + 交付格式），让反问本身没有必要。
  2. 要做 A/A 估噪声。IDRBench 自己的表格显示，同一配置重跑会差 1–2 分。我们之前建议每个 Agent 跑 3 次，就是为了量出这个噪声。两家的差距如果小于它，就判为同档。
  3. 不要把"和参考报告像不像"当主指标。IDRBench 的五项指标全是相似度。对我们来说，参考报告（如果有）只适合当辅助参照；主指标仍然是断言层的精确率和召回率（LiveDRBench 那套），再加上专家盲评。
  4. 如果以后真想测交互（比如比赛加一个"会不会问"的环节）：可以借用它的分阶段预算和成本记录，但要补上三样东西：空回答对照组、A/A 重跑、按题目模糊程度分层报告。"用户"最好是真人，至少要用真人校准过的模拟用户，而且模拟用户不要和被测模型同一家族。
