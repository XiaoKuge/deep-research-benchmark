评测工具一览：哪些能"喂报告、出分数"

回答索引页留言："在这么多篇文章里，软件可以直接用的有几个，即输入是一堆 DeepResearch 报告，输出是分数或者名次"

核查于 2026-10-28：逐个读了 23 篇的 GitHub / HuggingFace 仓库、README 和评测入口脚本，另查了文件夹外的初代 DeepResearch Bench。没有调用任何付费 API。

0结论

  • 23 篇里，能直接用在你自己 Prompt 上、喂报告就出分的只有 3 个：urlhealth、DeepFact-Eval Lite、MiroEval 的 point_quality。文件夹外还有初代 DeepResearch Bench 的 FACT。
  • 没有一个是一站式的。每个只管一个侧面：
    • urlhealth：链接是不是真的；
    • DeepFact：句子说得对不对；
    • FACT：引用是否支持对应的说法；
    • MiroEval：综合质量，评分标准由模型临时拟定。
  • 另有 2 个能用、但要你先写评分表：DRACO 的 rubric 评分库（支持扣分项，最适合装我们的"必答清单"），以及 DeepResearch Bench II 的评测脚本（只算召回）。
  • 没有现成可信的"5 份报告出名次"的工具。名次要靠上面几项分数，再加专家盲评排序。
  • 其余 18 篇：4 篇只能评它自带的题，3 篇代码不完整，11 篇没有评测代码或本身不是评测工具。

123 篇分类总表

A = 喂报告就出分，可用于任意 Prompt；B = 能用于新 Prompt，但要先写评分表或参考报告；C = 只能评它自带的题；D = 有代码但不完整或跑不起来；E = 没有评测代码或不是评测工具。

类论文 / 工具一句话

2能直接用的几个，细看

工具输入输出依赖和成本要注意
urlhealth 一个网址。要自己写几行代码，从报告里抽出所有链接，逐个调用 inspect(url)，没有命令行入口 每个链接分四类：活的 / 已失效（Wayback 有存档）/ 疑似编造（404 且没有存档）/ 未知；汇总成每份报告的"疑似编造比例" 不用大模型，不用搜索 API，免费；MIT 许可
  • 只查链接能不能打开，不查网页内容是否支持对应结论。
  • 完全编造、根本不存在的域名会判成"未知"，而不是"疑似编造"。
DeepFact-Eval Lite {"question": …, "response": 报告全文}，question 可以不填 事实分 = 核实为"有依据"的句子数 ÷ 被核验的句子数；附每句的判定和理由；每份报告最多核验 40 句 GPT-4.1 加 Serper（或 Tavily）搜索；论文给的 Lite 版准确率 77.9%，约 0.30 美元（按每份报告推断）
  • "查不到"也算不通过，对冷门内容偏严。
  • 仓库没有 LICENSE 文件，严格说不能复用。
  • 依赖很重，我们没有试跑。
MiroEval point_quality JSON 数组，每项 {query 或 rewritten_query, response}。我核对过 run_batch_eval.py 第 82 行和 --criteria_file 参数 每份报告 0–10 分，含覆盖、洞见、指令遵循、清晰 4 个固定维度，外加按题目自动生成的维度；名次要自己排 默认评委 gpt-5.1，走 OpenAI 或 OpenRouter；Apache-2.0 许可；装好依赖后 --help 能正常运行
  • 评分标准由模型自拟，没有参考答案，分数偏宽松。
  • 它的联网核事实模块依赖很重。
  • 是 MiroMind 自家框架（见精读里的利益关联）。
DRACO 的 rubric 库 题目 + 一份报告 + 你写的带权重评分表 0–1 的归一化分数，加每条要点"满足/不满足"及理由 默认用 Gemini，可以换成任意模型（自定义 generate_fn）；MIT 许可；分身用离线的假评委跑通了：权重 10 / 8 / −15 三条，得分 0.556，与公式一致
  • 评分表要自己写，这正是我们方案里"专家必答清单 + 汇总裁决"那一步。
  • DRACO 自带 100 题的评分表是明文，没有 canary 标记。
DRB II 评测脚本 报告放进 report/<Agent 名>/idx-1.md，评分要点按它的 jsonl 格式写 信息召回、分析、呈现三个维度各自的通过率，加总分；可以汇总成表 默认评委 GPT-5.5（2026-08 从 Gemini 换过来），任何 OpenAI 兼容接口都能接；--help 能正常运行
  • 只算召回，写错不扣分。
  • 仓库里没有生成评分要点的代码。
初代 DRB 的 FACT {id, prompt, article} 的 jsonl，报告要带网址引用 引用准确率（被引网页是否支持对应说法），以及平均有效引用数 gpt-5.4-mini 加 Jina 抓网页；Apache-2.0 许可；未试跑 报告里没有网址引用就没法评；如果某家只给【†】这类标记、没有网址，要先转换格式

3对"同一 Prompt、5 个 Agent"的拼法

没有一个工具能包办。按层拼起来，正好对应我们之前定的评分卡：

层用什么得到什么成本
链接是不是真的urlhealth每份报告的疑似编造和失效链接比例免费
引用是否支持结论初代 DRB 的 FACT引用准确率API 加 Jina
句子说得对不对DeepFact-Eval Lite（注意许可）事实正确率（每份最多 40 句）约 0.3 美元一份
该说的说全了没有DRACO 的 rubric 库，装我们的必答清单，再加负权重扣编造0–1 分，加逐条满足情况API
综合质量（仅作参考）MiroEval point_quality，5 份报告共用同一套标准0–10 分API
名次没有可信的现成工具用上面的分数，加专家盲评排序人工
  • 这些工具都只给单次分数，不给误差范围。5 个 Agent 各跑 3 次、再用 bootstrap 估误差，要自己做。
  • 5 份报告要用同一个评委模型，并且避开和被测 Agent 同一家族的模型。
  • 初代 DRB 和 DRB II 的官方评委都已经从 Gemini-2.5-Pro 换成了 GPT-5.5。用现在的代码跑出的分数，不能直接和论文里的数字比。

4复核说明

  • 我亲自跑过的：urlhealth。真实 arXiv 页面判为"活的"；编造的 arXiv 路径返回 404，Wayback 没有存档，判为"疑似编造"；真实 GitHub 仓库判为"活的"。
  • 分身跑过的：
    • rubric 库：用离线的假评委跑通了，没有调用真实 API；
    • MiroEval 和 DRB II：评测入口的 --help 能正常运行。
  • 没有试跑的：DeepFact、初代 DRB、DR³-Eval（依赖较重）。
  • MiroEval 的输入字段和 --criteria_file 参数，是我在仓库代码里逐行核对的。
  • 其他依据：各条的仓库链接、最后提交日期、许可证、看过的文件和行号，都记在会话临时目录的 tools_read13.json 和 tools_unread10.json 里。
  • 两处是推断：DeepFact 的 0.3 美元是按论文的表格推算为每份报告的成本；FACT 对【†】格式的处理没有试过。
