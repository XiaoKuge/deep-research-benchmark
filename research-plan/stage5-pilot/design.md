# 第五阶段小规模检验：检验设计

2026-10-29。在检验运行之前写定。验收标准见第四阶段方案第十节。

## 材料

- **六份报告。** 用三月那批现成的真实报告（第一阶段第 7.4 节），即同一个题目交给六个产品得到的报告。ChatGPT 用英文原文，不用中文译本。
- **匿名。** 六份报告随机编为 A 至 F。每份的第一行标题改为"报告某"，去掉标题中的产品名，正文不改。映射表另存，评委看不到。话题本身就是各家产品，所以匿名并不彻底，这是已知的局限。
- **题目卡**（`question-card.md`）。原题文本没有保存，题目是还原出来的，截止时间定为 2026-03-03。
- **深度地图**（`depth-map.md`）。是在读过部分报告之后写的，不符合"看到报告之前写好"的要求。

## 扰动版本

以其中一份较短、带链接的报告为底，做出四个版本，随机编为 P1 至 P4：

| 版本 | 改动 |
|---|---|
| 原版 | 不改 |
| 改错版 | 改错 3 处主要结论中的事实：两个评测分数，以及完成一次任务所需的时间 |
| 注水版 | 加入约三成正确、但与问题无关的背景，内容是搜索引擎和语言模型的发展史 |
| 编造版 | 把一处来源换成一个不存在的网站上的网址 |

每个版本由一个独立的评委完整评审，评委看不到其他版本。原版也用同样的方式单独评审一次，这样与扰动版的比较就是在同样的条件下进行的。

## 评委运行

所有评委都是 Claude 家族的模型，作为子智能体运行，彼此看不到对方的输出。

| 任务 | 评委 | 输出 |
|---|---|---|
| 环节评级与要点抽取（六份报告） | Opus 两次，第二次倒序阅读；Sonnet 一次 | `out/rating-*.json` |
| 断言核验（六份报告） | Opus，分两组 | `out/verify-opus-*.json` |
| 断言核验的稳定性（抽 15 条） | Sonnet，独立重核 | `out/verify-sonnet-subset.json` |
| 两两比较 | Opus 两次，第二次交换每对的先后，并倒序阅读 | `out/pairwise-*.json` |
| 扰动版的完整评审 | Opus，每个版本一个评委 | `out/single-P*.json` |
| 要点池的合并与判定 | Opus | `out/pool.json` |

计分程序是 `score.py`，结果写入 `results.json`。

（2026-10-30 补记）每次评委运行收到的提示词原文，以及每个输出文件对应哪份提示词、哪个模型、哪一天，存在评委子目录 [judges/](judges/README.md)。

## 本次检验检验不了的

- 跨厂商评委的稳定性，以及评委同源的偏向（验收标准 11）；
- 人工审计与独立专家判断（验收标准 9、10）；
- 题目卡和深度地图的出题环节，因为题目是还原的。
