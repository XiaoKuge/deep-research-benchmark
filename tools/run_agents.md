# 统一运行程序使用说明

程序是 `tools/run_agents.py`，测试是 `tests/test_run_agents.py`。依据是[规则手册](../research-plan/rules.md)第二节（冻结与申报、格式转换）、第五节（运行）、附录二（统一答复）、附录三（冻结申报表）和附录四（运行记录表）。

## 用途

运行日由主办方用一条命令，按运行计划调用每个参赛智能体：

- 把题目文件里的文字原样交给智能体，记下实际交出去的文字的校验值，与题目文本的校验值比对；
- 智能体反问时，回复附录二的统一答复，并记下它问了什么；问多少次答多少次；
- 到时长上限就停止，以届时已交付的内容为准；运行只在时长上限时结束（规则手册第五节）；
- 每次运行保存报告、输入、标准错误和运行日志，并按附录四的列在运行记录表里加一行。

只用 Python 自带的标准库，不需要装别的包。在 macOS 和 Linux 上运行；命令行方式用到命名管道，Windows 不支持。

## 一条命令

```
python3 tools/run_agents.py 运行计划.json --parallel 5
```

| 选项 | 作用 |
| --- | --- |
| `--parallel N` | 同时进行 N 次运行，默认 1（一个接一个）。每队 4 次运行，每次最长 120 分钟，一个接一个跑不完一天；运行日一般设成参赛队伍数。 |
| `--team 队伍名称` | 只跑这支队伍。 |
| `--question 题目名称` | 只跑这道题。 |
| `--version 提问版` 或 `--version 裸题版` | 只跑这个版本。 |
| `--rerun-reason 原因` | 重跑已经跑过的运行，见“重跑”一节。 |

程序先检查运行计划和全部申报文件。有任何问题（缺项、找不到文件、调用方式写错、队伍重名、同一道题的同一个版本列了两次），就把问题全部列出来并停止，一次也不运行，退出状态是 2。

检查通过后，程序按“题目在外、队伍在内”的顺序排好运行：同一道题的同一个版本，各队挨着开始；同时运行时，各队差不多同时开始，对开放时效型的题更公平。每次运行开始和结束各打印一行，结束那行写明已交付、未交付或到时长上限。

## 运行计划

运行计划是一个 JSON 文件（一种纯文本的数据格式），列出要跑的智能体、题目和版本：

```json
{
  "时长上限分钟": 120,
  "输出目录": "运行结果",
  "智能体": [
    "申报/示例队/申报.json",
    "申报/另一队/申报.json"
  ],
  "题目": [
    {"题目": "淡水湖", "版本": "提问版", "文件": "题目/淡水湖-提问版.txt"},
    {"题目": "淡水湖", "版本": "裸题版", "文件": "题目/淡水湖-裸题版.txt"}
  ]
}
```

| 字段 | 必填 | 说明 |
| --- | --- | --- |
| 时长上限分钟 | 否 | 默认 120（规则手册第五节，〔默认〕条款）。可以写小数，测试里用 0.02，即 1.2 秒。 |
| 输出目录 | 否 | 默认“运行结果”。 |
| 智能体 | 是 | 申报文件的路径，一队一份。 |
| 题目 | 是 | 每一项是一道题的一个版本，见下面。 |

题目的每一项：

| 字段 | 必填 | 说明 |
| --- | --- | --- |
| 题目 | 是 | 题目名称，用作目录名和运行记录的“题目”一列。 |
| 版本 | 是 | 只能是“提问版”或“裸题版”。 |
| 文件 | 是 | 题目文件。 |
| 校验值 | 否 | 题目冻结时算好的 SHA-256 校验值，见“输入校验值”一节。推荐填写。 |

路径都相对于运行计划文件所在的目录。

题目文件里放交给智能体的全文：提问版或裸题版的文字，后面接附录一的统一交付要求和说明。程序把文件的内容原样交出去，一个字节不加、不减、不改，换行也照原样。文件用 UTF-8 编码保存。

算校验值：在 macOS 上运行 `shasum -a 256 题目/淡水湖-提问版.txt`，在 Linux 上运行 `sha256sum 题目/淡水湖-提问版.txt`，取输出的第一段。大小写都可以。

## 申报文件

每支队伍一份申报文件，是 JSON 文件，字段对应附录三的冻结申报表，另加“调用方式”一项供程序调用：

```json
{
  "队伍名称": "示例队",
  "版本号或代码提交号": "1.0.0（提交 3f2a9c1）",
  "系统提示词文件": "系统提示词.md",
  "所用模型及其版本": "某模型，2026 年 9 月版",
  "工具和外部服务清单": ["网页搜索：某搜索服务", "网页读取：自己写的程序"],
  "格式转换方式": "题目原文从标准输入原样交给程序，不增删任何内容",
  "调用方式": {
    "方式": "命令行",
    "命令": ["python3", "agent.py"],
    "工作目录": "."
  },
  "运行环境说明": "Python 3.11 以上；需要环境变量 SEARCH_KEY",
  "需要的环境变量": ["SEARCH_KEY"],
  "申报日期": "2026-11-13",
  "申报人": "张三"
}
```

| 附录三的项目 | 申报文件里的字段 | 说明 |
| --- | --- | --- |
| 队伍名称 | 队伍名称 | 运行记录的“队伍”一列和目录名用它；各队不能重名。 |
| 版本号或代码提交号 | 版本号或代码提交号 | |
| 系统提示词全文（另附文件） | 系统提示词文件 | 文件路径，相对于申报文件所在的目录；文件必须存在。 |
| 所用模型及其版本 | 所用模型及其版本 | |
| 工具和外部服务清单 | 工具和外部服务清单 | 一段文字，或文字的列表。 |
| 格式转换方式：题目文本怎样放进输入 | 格式转换方式 | 给人看的说明；程序实际怎样交题目，由“调用方式”决定。 |
| 调用接口或程序包，运行环境说明 | 调用方式、运行环境说明、需要的环境变量 | 调用方式见下面和“两种调用方式”一节。“需要的环境变量”见下面。 |
| 申报日期、申报人 | 申报日期、申报人 | |
| 主办方计算的校验值 | 不用填 | 程序算出申报文件和系统提示词文件的 SHA-256 校验值，写进每次运行的日志。 |

除了“需要的环境变量”，以上字段都必须填写，不能空着。

“需要的环境变量”可以不写。写的话是一个列表，只写变量的名字，不写值，例如 `["SEARCH_KEY"]`；名字由字母、数字和下划线组成，不以数字开头。写了值（例如 `"SEARCH_KEY=abc"`）或者不是列表，程序检查时就报出来，一次也不运行。命令行方式下，程序只把这些名字和下面的固定集合交给智能体，见“两种调用方式”一节第 5 条；值由主办方在运行环境里设好，模型和检索服务的密钥怎样交给主办方另行公布。

“调用方式”有两种写法。命令行方式：

```
{"方式": "命令行", "命令": ["python3", "agent.py"], "工作目录": "."}
```

- 命令：推荐写成列表，一项一个词；也可以写成一行文字，程序按命令行的规则拆开。不经过命令解释器，所以不能用管道符号和重定向，需要的话自己写一个脚本。
- 工作目录：可以不写，默认是申报文件所在的目录；写了就相对于那个目录。

网络接口方式：

```
{"方式": "网络接口", "地址": "http://127.0.0.1:8000/run"}
```

- 地址：以 `http://` 或 `https://` 开头的网址。

## 两种调用方式

### 命令行方式

1. 每次运行，程序在工作目录里启动一次申报的命令，是一个全新的进程，不带其他运行的记忆（规则手册第五节“新会话”）。
2. 程序把题目文件的全文写进它的标准输入（UTF-8 编码），写完就关闭标准输入。智能体读到输入结束，就得到题目原文。
3. 智能体写到标准输出的全部内容就是报告，反问行除外（见“反问约定”）。写完退出即可。
4. 标准错误单独存成日志，可以写进度、检索记录、工具调用这些中间过程。
5. 环境变量：不整份沿用主办方运行环境的环境变量，只给一个固定的最小集合 `PATH HOME LANG LC_ALL TMPDIR USER SHELL TERM`（主办方环境里有的才给），加上申报里“需要的环境变量”点名要的，另加一个 `REPLY_PIPE`（见“反问约定”）。点名要的变量在主办方环境里没有设置的，就不给，名字记进运行日志。运行日志只记交出去的变量名，不记值。
6. 退出状态记进日志。退出状态不是 0，已经写出的报告照样算交付。
7. 报告的格式按开头判断：以 `%PDF` 开头的存为 `报告.pdf`；以 `<!doctype html` 或 `<html` 开头的存为 `报告.html`；其余存为 `报告.md`。

### 网络接口方式

1. 每次运行，程序向申报的地址发一个请求，方法是 POST，类型是 `application/json; charset=utf-8`，内容是：

   ```
   {"题目": "题目原文", "往来": []}
   ```

2. 智能体回应其中一种：
   - 报告：类型 `application/json`，内容 `{"报告": "报告全文"}`，报告是 Markdown 或网页的文字；
   - 报告文件本身：类型不是 `application/json`，例如 PDF 报告回 `application/pdf`，内容原样存下，格式判断同命令行方式；
   - 反问：见“反问约定”。
3. 回应状态不是 200（例如 500），这次运行算出错、未交付，状态和回应内容记进日志。连不上地址也一样。
4. 一次运行里因为反问可能有几个请求，都属于同一次运行。不同运行之间不要共享记忆，特别是同一道题的另一个版本。

## 反问约定

规则手册第五节规定：智能体提问或要求确认研究计划时，一律回复附录二的统一答复，并记下它问了什么；只能选择“批准计划”的，直接批准。统一答复原文是：

> 题目已包含全部信息，请按你的理解直接进行，并在报告中写明你的理解和假设。

### 命令行方式怎样反问

1. 在标准输出单独写一行：以 `[[反问]]` 开头，后面接问题，问题写在同一行；行尾要换行，写完立即刷新输出。
2. 然后打开环境变量 `REPLY_PIPE` 给出的文件，读到结束，就得到统一答复（一行文字）。这个文件是一个命名管道，答复送到之前读会一直等着。
3. 接着调研，继续往标准输出写报告。反问行不算报告内容。

Python 写法，几行就够：

```python
import os
import sys

question = sys.stdin.read()  # 题目原文

print("[[反问]] 你说的最大，是按面积算还是按蓄水量算？", flush=True)
with open(os.environ["REPLY_PIPE"], encoding="utf-8") as pipe:
    reply = pipe.read().strip()  # 统一答复

print("# 主要结论")
print("按面积理解：……")
```

命令解释器写法：

```
question=$(cat)
echo "[[反问]] 可以开始了吗？"
reply=$(cat "$REPLY_PIPE")
```

### 网络接口方式怎样反问

1. 回应 `{"反问": "问题"}`，类型 `application/json`。
2. 程序会向同一个地址再发一个请求，内容带上前面的全部往来：

   ```
   {"题目": "题目原文", "往来": [{"反问": "你的问题", "答复": "题目已包含全部信息，请按你的理解直接进行，并在报告中写明你的理解和假设。"}]}
   ```

3. 智能体照常回应报告；也可以再反问，“往来”会一项一项加长。

请求里没有会话编号：智能体看“往来”就知道自己问过什么、得到了什么答复。需要接着先前的工作做，用题目原文和“往来”对上即可。

Python 写法（只用标准库）：

```
import json
from http.server import BaseHTTPRequestHandler, HTTPServer

class Agent(BaseHTTPRequestHandler):
    def do_POST(self):
        request = json.loads(self.rfile.read(int(self.headers["Content-Length"])))
        if not request["往来"]:
            answer = {"反问": "要不要先确认研究计划？"}
        else:
            answer = {"报告": "# 主要结论\n……"}
        body = json.dumps(answer, ensure_ascii=False).encode("utf-8")
        self.send_response(200)
        self.send_header("Content-Type", "application/json; charset=utf-8")
        self.send_header("Content-Length", str(len(body)))
        self.end_headers()
        self.wfile.write(body)

HTTPServer(("127.0.0.1", 8000), Agent).serve_forever()
```

### 两种方式共同的规矩

- 每次反问回复一次统一答复，每次都是同一句话；问题全部记进运行记录“智能体是否提问，问了什么”一列和运行日志。
- 不设反问次数的上限：智能体问多少次，程序就答多少次。运行只在时长上限时结束（规则手册第五节），一直反问的智能体，也是到时长上限才停止，以届时已交付的内容为准。
- 等答复的时间算在时长上限之内；答复是立即给的。
- 规则手册第五节说“只能选择‘批准计划’的，直接批准”，指的是产品界面上只给“批准计划”一个选项的智能体，由运行的人直接批准。命令行和网络接口两种方式没有“批准计划”这种消息：智能体要确认研究计划，也照上面的写法反问，程序回的是附录二的原文，与别的反问一样。不想反问的，在自己的程序里直接批准、接着做即可。

## 时长上限

- 从启动命令（或发出第一个请求）开始计时。时长上限默认 120 分钟（〔默认〕条款），在运行计划里改。
- 到时立即停止：命令行方式强行结束整个进程组，包括它启动的子进程；网络接口方式不再等待回应。
- 以届时已交付的内容为准：命令行方式，到那时已经写到标准输出的内容就是报告；网络接口方式，到那时还没收到完整的回应，就是没有交付。
- 没有交付，或者交付的内容全是空白，记为未交付：不存报告文件，运行记录“文件名”一列写“未交付”。
- 运行日志里“是否超时”为 true，“退出状态”写“到时长上限，由运行程序停止”。

## 输入校验值

- 程序计算实际交给智能体的文字的 SHA-256 校验值：命令行方式是真正写进标准输入的字节，智能体提前关闭标准输入的，只算写进去的部分；网络接口方式是请求里“题目”一栏的文字。
- 拿它和题目文本的校验值比对：运行计划里写了“校验值”，就用它；没写，就用程序读到的题目文件的校验值。推荐题目冻结时就把校验值写进运行计划，这样题目文件之后被人改过也能发现。
- 两者相同，运行记录写“一致”，否则写“不一致”。不一致的，按规则手册第十节处理：原因在队伍申报的格式转换的，该次运行作废，记为未交付；原因在主办方的，重跑一次。
- 智能体没能启动（例如命令写错），什么也没交出去，也记为“不一致”；原因看运行日志里的“错误”。

### 运行日志

`运行日志.json` 每次运行一份，主要字段：

| 字段 | 内容 |
| --- | --- |
| 队伍、题目、版本、调用方式 | 这次运行是谁、哪道题、怎样调用的 |
| 开始、结束、用时秒 | 完整的时间，带时区 |
| 时长上限秒、是否超时 | |
| 退出状态 | 命令行方式是进程的退出状态；网络接口方式是最后一个回应的状态；到时被停止的写明原因 |
| 是否交付、报告文件、报告校验值 | |
| 输入文件、输入校验值、题目文本校验值、题目文本校验值来源、输入校验值是否一致 | 来源是“运行计划”或“题目文件” |
| 反问 | 每次反问的问题、时间和给出的答复 |
| 标准错误文件、错误 | 错误写程序发现的问题，例如命令启动不了、地址连不上 |
| 交给智能体的环境变量、申报要的、主办方环境里没有的环境变量 | 只记名字，不记值；网络接口方式不启动程序，这两项为空 |
| 是否重跑、重跑原因 | |
| 申报文件、申报文件校验值、系统提示词文件校验值 | 附录三“主办方计算的校验值” |

### 运行记录

`运行记录.csv` 是逗号分隔的表格文件，每天一份，每次运行加一行，用表格软件可以直接打开（UTF-8 编码，开头带编码标记，中文不会乱码）。列与附录四一字不差：

| 列 | 写什么 |
| --- | --- |
| 题目 | 运行计划里的题目名称 |
| 版本 | 提问版或裸题版 |
| 队伍 | 申报文件里的队伍名称 |
| 日期 | 这次运行开始的日期 |
| 开始 | 时、分、秒，本机时区；完整时间在运行日志里 |
| 结束 | 同上 |
| 输入校验值是否一致 | 一致或不一致 |
| 智能体是否提问，问了什么 | “否”；或“是：”后接问题，几个问题用“；”隔开 |
| 是否重跑，原因 | “否”；或“是：”后接原因 |
| 文件名 | 报告文件相对于当天目录的路径；没有交付写“未交付” |

## 重跑

- 同一天再运行同一份计划，已经有结果的运行会跳过，不会覆盖。程序中途断了，可以直接再运行一遍，把剩下的跑完；断的那一次要重跑，按下面的办法。
- 因主办方运行环境的故障中断的，允许重跑一次（规则手册第五节，〔默认〕条款）；由主办方判定，判定理由公开。智能体自身出错不重跑。重跑时写明原因：

  ```
  python3 tools/run_agents.py 运行计划.json --team 示例队 --question 淡水湖 --version 提问版 --rerun-reason "运行机器断电"
  ```

- 重跑的结果存在“提问版-重跑”这样的目录里，原来的结果保留；运行记录加一行，“是否重跑，原因”写“是：运行机器断电”。
- 同一次运行只能重跑一次，再重跑会被跳过。今天还没跑过的运行，不能用重跑的方式跑。

## 测试

在仓库根目录运行：

```
python3 -I -m unittest discover -s tests -p test_run_agents.py -v
```

测试用这几种假智能体：回显程序、会反问的程序（包括问 25 次、一直问到时长上限的）、超时的程序（时长上限设成 1.2 秒）、打印自己拿到哪些环境变量的程序，以及用标准库起在线程里的本地网络接口。测试还会把本说明里的运行计划、申报文件和 Python 反问写法原样拿出来跑一遍，确认说明与程序一致。
