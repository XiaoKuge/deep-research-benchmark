# 模拟出题者使用说明（tools/simulate_setter.py）

还没有真人出题者的阶段，主办方用这个程序让大模型按[出题手册](../research-plan/question-handbook.src.html)的出题七步出一道题：写评委版题目卡，写提问版和裸题版，两位"出题人"各自独立写深度地图并用数鱼的办法对照，另一个模型只看交给智能体的两个版本做泄露检查，再换一家不联网做闭卷对照。输出一个题目目录，题目卡和深度地图的格式照出题手册第八节的模板。依据还有[规则手册](../research-plan/rules.md)第三节（三个版本、出题要求）和第四节（深度地图的写完标准、五道关）。

模型通过[模型调用层](models.md)（`tools/models.py`）调用，每一次调用的提示词全文、回答全文、厂商、模型和时间都记进题目目录里的调用记录。只用 Python 自带的标准库。测试在 `tests/test_simulate_setter.py`，一律用回放方式，不真的调用模型。

## 一条命令

先只估算，看要调用几次：

```
python3 tools/simulate_setter.py --topic "城市里的萤火虫" --asker "一位小区物业的绿化主管" \
    --kind 练习题 --id 萤火虫 --estimate
```

再在调用次数上限内真跑（真实调用必须给 `--max-calls`）：

```
python3 tools/simulate_setter.py --topic "城市里的萤火虫" --asker "一位小区物业的绿化主管" \
    --kind 练习题 --id 萤火虫 --max-calls 20
```

只给领域，让模型按出题手册第 1 步的条件选话题：

```
python3 tools/simulate_setter.py --domain "城市生态" --question-type 看似简单型 --kind 正式题 --max-calls 20
```

照一份录好的调用记录重放，不调用模型（测试就是这样跑的）：

```
python3 tools/simulate_setter.py --topic "城市里的萤火虫" --kind 练习题 --id 萤火虫-重放 \
    --replay simulation/questions/萤火虫/调用记录.jsonl
```

| 选项 | 作用 |
| --- | --- |
| `--topic 话题` | 话题。和 `--domain` 至少给一个。 |
| `--asker 提问者设定` | 提问者设定。不给就让模型按手册设计一位具体的提问者。 |
| `--domain 领域` | 只给领域，让模型在这个领域里按第 1 步的五个条件选话题。 |
| `--question-type 看似简单型` 或 `开放时效型` | 题型。不给就让模型按话题选。 |
| `--kind 练习题` 或 `正式题` | 必填。写进元数据；资料站的题库页据此决定公开全文还是只公开深度地图的校验值。 |
| `--id 题目标识` | 题目目录的名字，也是深度地图上的"题目编号"。不给就用"模拟-运行编号"。 |
| `--out 目录` | 题目目录放在哪里，默认仓库根目录下的 `simulation/questions/`。 |
| `--setter`、`--map-a`、`--map-b`、`--leak-checker`、`--closed-book` | 各角色用哪家：模型调用层认得的厂商名，现在是 `claude`、`codex`、`kimi`、`google`（Google 的 Antigravity 命令行 `agy`），见"角色和厂商"一节。 |
| `--model 厂商=模型` | 给某一家指定模型，可以写多次，例如 `--model claude=claude-opus-5-5`。不给就用该命令行的默认模型。 |
| `--max-extra-rounds N` | 两人对照没写全时，最多补查几轮，默认 2。 |
| `--estimate` | 只估算：不调用模型，不写题目目录，只打印将发起的调用次数。 |
| `--replay 调用记录文件` | 回放：回答从录好的调用记录里取，可以写多次。 |
| `--max-calls N` | 真实调用的次数上限。真实调用时必须给；只估算时用来判断会不会超过。 |
| `--timeout-seconds N` | 单次调用的时长上限，默认 1800 秒。 |

退出状态：

- 0：题目目录写好了。题目过没过各项检查，看打印的摘要和 `元数据.json` 的"检查结果"。
- 1：出题中途停止（例如第 2 步判断挖深不改变结论、回答不是可读的 JSON、到了调用次数上限）。目录里只有 `元数据.json`（状态为"中途停止"，写明原因）和已经发生的调用记录。
- 2：选项有问题，或者题目目录已经存在。这时一次也不调用。程序不覆盖已有的目录，重跑请换一个 `--id` 或先删掉旧目录。

## 出题七步怎样变成调用

| 手册的步骤 | 调用的任务名 | 角色 | 工具限定 | 模型看到的东西 | 产出 |
| --- | --- | --- | --- | --- | --- |
| 1 选话题、2 浅答案、3 评委版 | 出题-评委版 | 出题人 | 只读网页 | 手册第一至六节原文；话题或领域、提问者设定、题型 | 话题、题型、浅答案、挖深会不会改变结论、提问者、用途、问题 |
| 3 提问版和裸题版 | 出题-提问版和裸题版 | 出题人 | 只给材料 | 手册第一至六节；评委版四栏（不给浅答案和调研笔记） | 提问版、裸题版 |
| 4 深度地图 | 出题-深度地图-甲-第1轮、出题-深度地图-乙-第1轮 | 甲、乙 | 只读网页 | 手册第一至六节；评委版四栏。看不到对方写的任何东西 | 各自一份深度地图：浅答案、转折点、要点表 |
| 4 两人对照 | 出题-两人对照-第1轮 | 出题人 | 只给材料 | 两份深度地图 | 两人都列到的核心要点配对；合并后的深度地图 |
| 4 补查 | 出题-深度地图-甲-第2轮 …… 出题-两人对照-第2轮 | 甲、乙、出题人 | 同上 | 自己上一轮的地图，加上只有一人列到的核心要点 | 新的地图和对照 |
| 5 自查 | 不调用模型 | 程序 | | | 写完标准五条的机械检查，写进元数据 |
| 6 泄露检查 | 出题-泄露检查 | 泄露检查人 | 只给材料 | 只有提问版和裸题版的全文（就是交给智能体的两个文件）和手册第六节"红笔批改"。没有深度地图，也没有评委版和调研笔记 | 三个问题的回答 |
| 7 闭卷对照 | 出题-闭卷对照-作答 | 闭卷对照 | 只给材料 | 提问版全文，和交给智能体的一字不差 | 不联网的回答 |
| 7 闭卷对照 | 出题-闭卷对照-比对 | 出题人 | 只给材料 | 合并后地图的核心要点，加上不联网的回答 | 答到了哪几条核心要点 |

每一步要求模型只回复一个 JSON 对象（一种纯文本的数据格式），程序再按手册的模板写成文件。几处由程序做、不交给模型：

- 截止时间一栏统一写"只使用截至〔运行当日〕已经公开的信息。"
- 交付要求和说明，一字不改，程序运行时从手册原文取出：`题目卡.txt` 的第四部分照出题手册题目卡模板的写法（「【交付要求】」另起一行）；交给智能体的 `提问版.txt` 和 `裸题版.txt` 照规则手册附录一的写法（「交付要求：」），和新手包里的练习题一个字节都不差。两份手册里这段话的文字相同，只是标题的写法不同。
- 数鱼的计算、"写全了没有"的结论、闭卷对照"保留还是不保留"的结论，都由程序按手册的规则算。

出题人一侧的提示词附上手册第一至六节的原文。原文是程序运行时从 `research-plan/question-handbook.src.html` 读出来的，所以手册改了，提示词跟着变（录好的调用记录按提示词校验值回放时，也就对不上了）。

有两处检查不通过时，程序如实记下，不自动改题：

- 第 2 步：出题人判断挖深不会改变结论，程序停止（退出状态 1），按手册应当换题。
- 第 6 步发现泄露，或第 7 步闭卷就答到了大部分核心要点：题目目录照常写出，记录里写明"未通过"或"改题、换题"，按手册应当回到第 3 步、第 1 步或第 2 步，由主办方决定。

## 数鱼的办法怎样算

按出题手册第三节第 4 步和规则手册第四节第 2 道关：

- 甲列了 a 条核心要点、乙列了 b 条：取各自地图上重要性为"核心"的条数。
- 两人都列到的 c 条：取对照一步给出的配对里合规的对数。只认甲的一条核心要点配乙的一条核心要点、一对一；配到一般要点、编号不存在、一条要点配了两次的，舍去，并在两人对照记录里写明原因。
- 估计总数 = a × b ÷ c；合并后的条数 = a + b − c。两者相差不到 1 条〔默认〕，就算写全了。
- c = 0 时无法估计，记为"离写全还很远"，继续查。

| 甲 | 乙 | 都列到 | 估计总数 | 合并后 | 结论 |
| --- | --- | --- | --- | --- | --- |
| 4 | 5 | 4 | 5 | 5 | 写全了 |
| 4 | 4 | 2 | 8 | 6 | 还差约 2 条，继续查 |

（这两行就是手册里的例子，也是测试的期望值。）

没写全时，按手册"两人针对只有一个人列到的方向，各自再查一轮，然后重新对照"：下一轮每人拿到自己上一轮的地图和只有一人列到的核心要点，重写一份完整的地图，再对照一次。最多补查 `--max-extra-rounds` 轮；到了上限还没写全，照常写出题目目录，写完标准第 4 条记为没有满足。注意：只有第 1 轮两人是完全独立的；补查时两人已经看过对方独有的方向，这是手册规定的做法。

## 角色和厂商

| 角色 | 做什么 | 默认 | 要求 |
| --- | --- | --- | --- |
| 出题人 `--setter` | 评委版（只读网页）、两个版本、两人对照、闭卷比对 | claude | 评委版要读网页，google 不能当 |
| 甲 `--map-a` | 写深度地图（只读网页） | claude | google 不能当 |
| 乙 `--map-b` | 写深度地图（只读网页） | codex | 默认和甲不同家；google 不能当 |
| 泄露检查人 `--leak-checker` | 泄露检查（只给材料） | google | 尽量和出题人不同家（手册：换一个人看） |
| 闭卷对照 `--closed-book` | 不联网作答（只给材料） | google | 必须和写过深度地图的厂商都不同 |

默认的分工用到 Claude（Anthropic）、Codex（OpenAI）、Gemini（Google）三家，与资料站上写的一致；Kimi（月之暗面）是备用。写深度地图要读网页，而 google 不能用于只读网页一档（见 [models.md](models.md) 的 google 一节），所以两位出题人是 claude 和 codex，google 做只给材料的泄露检查和闭卷对照。

`--closed-book` 和 `--map-a`、`--map-b` 中任何一个相同，程序直接拒绝（退出状态 2）。

**某一家不能用于这一档时。** 挑厂商之前先查模型调用层的 `usable()`：计划的厂商不能用于这一步的工具限定（目前只有 google 不能用于只读网页一档），就不发调用，直接按下面的顺序换一家，记一条替代，原因写明"不能用于只读网页一档"。这一家不算不可用：只是这一次不用它，别的只给材料的步骤照常用它。所以把 `--map-b` 配成 google，三轮地图都会换成别家，每一轮记一条替代。只估算时同样这样挑，估算出的各家次数与真实运行一致。

**某一家不可用时。** 一次调用失败、超时或找不到命令行（模型调用层抛出调用失败），程序就把这一家记为本次运行中不可用，后面的步骤不再用它，这个角色以后都用换来的那一家，然后按下面的顺序换一家：

- 甲、乙：先避开闭卷对照配置的那一家（给闭卷对照留出一家），再尽量和另一位出题人不同；
- 泄露检查人：尽量和出题人不同；
- 闭卷对照：只从没写过深度地图的厂商里选；一家也没有，就记为"未做"，写明原因，不用别的回答代替；
- 出题人：按模型调用层列出厂商的顺序（claude、codex、kimi、google）选可用的。

其余条件相同时也按这个顺序。除闭卷对照外，任何角色一家可用的都没有，程序停止。每一次替代都记进 `元数据.json`（"角色"下每个角色的"替代"，以及"厂商不可用"），深度地图和各项记录里写到这个角色时，也写明"配置的是哪家、在哪一步换成了哪家"（同一种替代在后面几轮又发生的，只写第一次）。

替代记录的字段：`步骤`（任务名里的步骤，例如"深度地图""闭卷对照"）、`任务`（任务名，例如"出题-深度地图-乙-第1轮"）、`原来的厂商`、`改用的厂商`、`原因`（跳过的每一家和原因，例如"kimi：调用失败：……；google：……不能用于只读网页一档……"）。模拟评审 `run.json` 的 `substitutions` 用同一种格式；挑厂商和写替代记录的代码在 [substitutes.py](substitutes.py)，两个程序共用。失败的那次调用本身也在调用记录里（真实调用时）。两位出题人最后用了同一家的，元数据的"说明"里写明：两次调用仍互相看不到，但同一家的模型容易找到同样的几条，数鱼的估计可能偏低。

**现在的情况。** 本机 kimi 的登录已经过期；google 的 `agy` 已经登录（2026 年 10 月 30 日），只能用于只给材料档（见 [models.md](models.md)）。默认分工里不用 kimi：甲 claude、乙 codex，泄露检查和闭卷对照 google。kimi 重新登录以后，可以写 `--map-b kimi` 等让它当某个角色。

## 输出目录

```
simulation/questions/<题目标识>/
  题目卡.txt          题目卡三个版本，照手册题目卡模板：一、评委版 二、提问版 三、裸题版 四、交付要求和说明
  提问版.txt          交给智能体的全文：提问版，空一行，接规则手册附录一的交付要求和说明，一字不改
  裸题版.txt          同上，裸题版
  深度地图.txt        合并后的深度地图，照手册深度地图模板的六部分：浅答案、转折点、要点表、
                      两人对照记录、泄露检查记录、闭卷对照记录
  深度地图校验值.txt  深度地图.txt 的 SHA-256 校验值
  深度地图.json       同一份深度地图的数据形式（要点的层级、重要性、出处），供模拟评审程序读取
  两人对照记录.md     每一轮甲和乙各自的完整地图、配对、舍去的配对、只有一人列到的核心要点、数鱼的计算
  泄露检查记录.md     检查人、日期、三个问题的回答、结论，以及检查的原文
  闭卷对照记录.md     所用模型、日期、答到了哪些核心要点、结论，以及不联网的回答原文；没做时写明原因
  元数据.json         练习题或正式题、生成时间、各角色配置和实际用的厂商和模型、每一步的调用、
                      替代和不可用的记录、调用次数、深度地图校验值、检查结果
  调用记录.jsonl      本次全部调用记录（模型调用层的格式，每行一条）
```

- `提问版.txt` 和 `裸题版.txt` 可以直接写进[统一运行程序](run_agents.md)的运行计划。
- 核对深度地图没有被改过：在题目目录里运行 `shasum -a 256 -c 深度地图校验值.txt`（Linux 上用 `sha256sum -c`）。
- 正式题的目录里同样有全文；赛前对外只公布校验值，由资料站的题库页负责（只显示 `深度地图校验值.txt`）。
- 资料站的题库页由 `python3 -I site/build_simulation.py` 生成。练习题公开全文；正式题要公开时，主办方在 `元数据.json` 里加上 `"已公开": true`，再运行一次生成器。没有这个字段的正式题按未公开处理，页面上不显示题目卡、深度地图和调用原文。
- 深度地图的"写成日期"是生成那天。地图在任何报告存在之前由程序写成。

`元数据.json` 的"检查结果"：

| 字段 | 含义 |
| --- | --- |
| 写完标准 | 规则手册第四节五条的机械检查：浅答案（写了）、转折点（写了，用到的要点里至少一条在内部联系或本质层，且都有出处）、四层都查过（要点表里每一层都有要点；没有要点的层，"找不到要点的层"里要有一句同时写到这一层的名字、查了什么（"查""检索""搜索"）和没有找到（"没有""找不到"等），只提到层的名字不算）、核心要点写全（最后一轮数鱼的结论）、两人对过（每一轮甲和乙的地图都真的写出了要点，并且做了对照） |
| 四层里没有要点的层 | 列出来，方便核对 |
| 泄露检查 | 通过：三个问题都答"没有"；否则未通过 |
| 闭卷对照 | 保留、改题、换题、未做，或无法对照（地图上没有核心要点） |
| 全部通过 | 以上全部满足、泄露检查通过、闭卷对照为保留 |

这些是程序能机械判断的部分；要点的对错、核心判得准不准，还要靠领域专家审阅（规则手册第四节第 3 道关）。

## 只估算

`--estimate` 不调用模型、不写题目目录，把整个流程用占位回答走一遍，打印将发起的调用次数：按厂商、按步骤，以及是否超过 `--max-calls`。占位的两人对照没有重合，所以补查轮数会用满，打印的是上限；同时打印第一轮就写全时的次数。默认设置下最多 14 次（评委版 1、两个版本 1、三轮各 3、泄露检查 1、闭卷作答 1、闭卷比对 1），第一轮就写全时 8 次；按厂商是 claude 9 次、codex 3 次、google 2 次。估算按 `usable()` 挑厂商，不能用于某一档的厂商已经换好，与真实运行一致；估算假定其余配置的厂商都可用，某一家不可用时，每换一家多一次失败的调用。

## 回放

`--replay` 读录好的调用记录，按任务名、厂商和提示词校验值取回答（规则见 [models.md](models.md) 的"回放"一节）。录好的记录可以是上一次真实运行的 `调用记录.jsonl`，也可以手写；手写时每行只写 `task`、`vendor`、`answer` 三个字段，不写 `prompt_sha256`，就匹配这个任务、这一家的任何提示词。`answer` 是那一步模型该回的 JSON 文字。

回放材料里状态为"失败"或"超时"的记录，回放时当作那一家在那一步不可用，照上面的替代规则换一家，原因取那条记录的 `error`。这样，重放一次真实运行时，当时的替代会照样发生；测试也用它模拟 kimi 登录过期、codex 额度用完（乙配置成 kimi，`--map-b kimi`）：

```
{"task": "出题-深度地图-乙-第1轮", "vendor": "kimi", "status": "失败", "error": "退出状态 1；……401……"}
{"task": "出题-深度地图-乙-第1轮", "vendor": "codex", "status": "失败", "error": "退出状态 1；……额度用完……"}
{"task": "出题-深度地图-乙-第1轮", "vendor": "claude", "answer": "{\"浅答案\": ……}"}
```

回放时缺了某一步的回答（又没有录下那一家在那一步失败），程序停止（退出状态 1）。

## 测试

在仓库根目录运行 `python3 -I -m unittest discover -s tests -v`。本程序的测试在 `tests/test_simulate_setter.py`，全部用手写的回放材料，覆盖：一条命令写出完整的题目目录；题目卡和深度地图逐行对照手册第八节模板（测试自己从手册源文件读模板），交付要求和说明一字不改（题目卡照手册模板，交给智能体的两个文件照规则手册附录一），校验值和文件一致；数鱼的计算（手册表里的两行，以及没有重合的情况）和补查一轮；泄露检查的提示词里只有两个版本、没有深度地图和调研笔记的任何文字；第 1 轮两位出题人互相看不到；闭卷对照的厂商没写过地图、只给材料、提示词就是提问版全文；闭卷答到大部分核心要点时不保留；某一家不可用时的替代和记录；闭卷对照没有可用厂商时记为未做；只估算的调用次数；真实调用不给上限时拒绝运行；第 2 步不通过时停止。
