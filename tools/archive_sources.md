# 网页存档程序使用说明

[规则手册](../research-plan/rules.md)第五节"存档"一条要求：报告引用的网页在运行后 24 小时内存档，附存档时间和校验值；第九节的复核包要公开这些存档。程序 `tools/archive_sources.py` 做这件事：读一份报告，提取里面的全部网址，逐个取回，把内容按校验值保存，再写一份清单。

它只用 Python 自带的标准库，不调用任何第三方存档服务，内容全部存在主办方自己的目录里。

## 用法

先只列出网址，确认提取得对。这一步不连网：

```
python3 -I tools/archive_sources.py 报告文件 --list
```

每行打印一个网址；最后在错误输出上说明共几个网址、跳过了几个图片地址。

确认无误后正式存档：

```
python3 -I tools/archive_sources.py 报告文件 --out 存档目录
```

| 选项 | 含义 | 默认 |
| --- | --- | --- |
| `--list` | 只列出网址，不取回 | 不加 |
| `--out` | 存档目录。每次存档用一个新目录，例如目录名带上报告编号和存档日期 | 不用 `--list` 时必须给 |
| `--timeout` | 单个网址的时长上限，单位秒 | 30 |
| `--max-bytes` | 单个网址的大小上限，单位字节 | 52428800（50 兆字节） |

运行中每个网址打印一行进度，最后一行汇总成功几个、失败几个。只要报告能读出来，程序就把全部网址走完，以退出状态 0 结束；个别网址失败只记在清单里。

存档目录里已经有 `manifest.json` 时，程序拒绝运行（退出状态 2），不覆盖之前的存档。

程序使用本机的代理设置（环境变量或系统设置）。请求里的 `User-Agent` 一栏按惯例写成 `Mozilla/5.0 (compatible; deep-research-benchmark-source-archiver/1.0)`，表明这是程序，不冒充浏览器；拒绝程序访问的网站会记成相应的状态码。

## 网址怎样提取

按报告文件的扩展名判断格式：`.html` 和 `.htm` 按网页解析，其余（`.md`、`.txt` 等）按 Markdown 解析。

Markdown 报告取这几处：

- 链接 `[文字](网址)`，包括嵌套方括号 `[[来源](网址)]`、网址里带圆括号、网址用尖括号包起来的 `[文字](<网址>)`；
- 尖括号包起来的网址 `<https://...>`；
- 正文里的裸网址，包括参考式链接的定义行 `[1]: https://...`。

网页报告取这几处：

- `<a>` 和 `<area>` 的 `href`，其中 `&amp;` 这类写法会还原成 `&`；
- 正文文字里的裸网址。
- 不取 `<script>` 和 `<style>` 里的文字，不取 `<link>` 的 `href`：那是样式表和图标，不是被引网页。

两种格式共同的规则：

- 只取以 `http://` 或 `https://` 开头的网址。相对地址、页内锚点、邮件地址都不取。
- 图片不算被引网页：Markdown 图片 `![说明](网址)` 和网页的 `<img src>` 都跳过，只计数。
- 裸网址遇到空白、中文字符、中文标点、引号、尖括号或方括号就结束；末尾粘着的英文句读（`.,;:!?*`）和没有配对的右括号会去掉。网址里含中文的，只有写成 Markdown 链接或 `href` 才能完整取出。
- 去掉 `#` 之后的部分再去重：同一页面的不同锚点只取一次（取回网页时本来也不发送 `#` 之后的部分）。顺序按在报告里第一次出现的位置。
- 不带 `http://` 或 `https://` 的地址（例如只写 `example.com/page`）不取，因为没法和正文里的普通文字可靠地区分。

用第五阶段试评的六份报告做过离线检查（只提取，没有取回）：

- 报告 E 提取出 6 个网址，和逐条人工核对的结果一致。
- 报告 A、B、C、F 正文里没有网址。A 的出处是"【8†L183-L189】"这类引用标记，没有附网址。
- 报告 D 里 291 个完整网址全是来源图标和标志图片，都被跳过；它的出处列表只有 `clickforest.com/en/blog/ai-tools-comparison` 这样不带协议的显示文字，所以提取出 0 个网址。规则手册第六节要求"链接必须保留〔默认〕"，这种情况应当在收报告时就要求交回带链接的版本，而不是让存档程序去猜。

## 存档目录和清单

```
存档目录/
  manifest.json            清单
  content/
    <校验值>.html          取回的内容：文件名是内容的校验值，扩展名按内容类型
    <校验值>.pdf
```

- 校验值用 SHA-256 算法，对取回的原始字节计算，写成 64 位十六进制（小写）。任何人都能用 `shasum -a 256 文件名` 核对文件内容和清单是否一致。
- 扩展名按内容类型猜：`text/html` 用 `.html`，`application/pdf` 用 `.pdf`，猜不出用 `.bin`。内容完全相同的几个网址共用一个文件。
- 保存的是服务器返回的原始字节，不解压、不转码、不改写；不另取网页里引用的图片、样式表和脚本。

清单 `manifest.json` 是一个 JSON 文件，顶层字段如下：

| 字段 | 含义 |
| --- | --- |
| `report` | 报告文件路径，照命令行上写的记录 |
| `report_sha256` | 报告文件的校验值，用来对应是哪一版报告 |
| `started_at`、`finished_at` | 整次存档的开始时间和结束时间 |
| `timeout_seconds`、`max_bytes` | 这次用的时长上限和大小上限 |
| `skipped_image_urls` | 跳过的图片地址个数 |
| `entries` | 每个网址一条，顺序和提取顺序相同 |

`entries` 里每条的字段：

| 字段 | 含义 | 失败时 |
| --- | --- | --- |
| `url` | 报告里写的网址（去掉 `#` 之后的部分） | 总有 |
| `final_url` | 跟随重定向以后实际取到内容的网址；中文等字符已转成百分号编码 | 没连上时为 `null` |
| `status` | 服务器返回的状态码 | 没收到响应时为 `null` |
| `content_type` | 服务器声明的内容类型，原样记录 | 没收到响应时为 `null` |
| `bytes` | 内容的字节数 | 没保存内容时为 `null` |
| `sha256` | 内容的校验值 | 没保存内容时为 `null` |
| `file` | 内容文件在存档目录里的相对路径 | 没保存内容时为 `null` |
| `fetched_at` | 这个网址取回结束或放弃的时间 | 总有 |
| `error` | 错误原因；成功时为 `null` | 总有 |

所有时间都用协调世界时，精确到秒，写成 `2026-10-30T08:15:02Z` 这样，末尾的 Z 表示协调世界时。

## 失败怎样记录

一个网址出了任何问题，都只写进它那一条的 `error`，然后接着取下一个，不中断整次存档。

| 情况 | `status` | 是否保存内容 | `error` 的写法 |
| --- | --- | --- | --- |
| 状态码 400 及以上，例如 404 | 照记 | 保存服务器返回的错误页，作为当时打不开的证据 | `服务器返回 404 Not Found` |
| 超时 | 没收到响应时为 `null` | 不保存 | `超时：30 秒内没有取回` |
| 超过大小上限 | 照记 | 不保存：只存半截，校验值就没有意义 | `内容超过大小上限 52428800 字节，没有保存` |
| 重定向没有完成：超过 10 次、形成循环、没给新地址或转到其他协议 | 最后一次重定向的状态码 | 保存服务器返回的内容 | `重定向没有完成（状态码 302）：……` |
| 连不上：域名查不到、拒绝连接、证书校验失败等 | `null` | 不保存 | `无法连接：` 后接系统给出的原因 |
| 其他错误 | 视情况 | 不保存 | `取回出错：` 后接错误类型和说明 |

时长上限的算法：连接和等待响应的每一步都不超过设定的秒数；下载正文时每读一块检查一次总用时，超过就放弃。

失败的网址要重取时，把清单里 `error` 不为空的网址抄进一个文本文件（每行一个），再用本程序存到一个新目录。两次的清单都留着。

## 不做的事

- 不调用任何第三方存档服务，也不把网址交给任何外部服务；只直接向网址所在的服务器发请求。
- 不执行网页里的脚本。靠脚本加载正文的网页，存下来的可能只是一个空壳；需要时由主办方另外用浏览器保存，并在复核包里注明。
- 不登录，不带任何登录信息。要登录或付费才能看的页面，记下服务器返回的状态码和页面。
- 不负责定时。规则要求运行后 24 小时内存档，由主办方在运行当天对每份报告执行一次。

## 测试

在仓库根目录运行 `python3 -I -m unittest discover -s tests -v`。存档程序的测试在 [tests/test_archive_sources.py](../tests/test_archive_sources.py)：

- 用线程里运行的本机测试服务器覆盖成功、重定向、404、超时四种情况，另有超过大小上限和不覆盖旧存档；
- 用 Markdown 和网页两种报告检查网址提取，并对试评报告 D、E 做离线提取检查。

测试不连外网。
