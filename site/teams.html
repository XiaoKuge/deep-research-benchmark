参赛队伍技术文档

智能体怎样申报、主办方怎样调用它、运行环境、时长上限和统一答复。这里的约定就是主办方统一运行程序的约定，程序是 tools/run_agents.py，完整的使用说明见统一运行程序使用说明。新手包里有申报表模板、练习题和一个示例智能体，在本机几秒钟就能跑通一次。

一次运行的经过

你交出冻结的智能体，主办方在运行日按同一套办法调用每一个智能体。每个智能体跑 2 道题 × 2 个版本，共 4 次。

  1. 冻结并申报。题目公布前，提交冻结申报表，以及供主办方调用的程序或接口地址。此后到比赛结束不得修改。见申报智能体。
  2. 主办方统一运行。运行日当天，主办方按运行计划逐个调用。每次运行都是全新的进程或请求，不带其他运行的记忆。见调用方式。
  3. 题目原文原样交出。提问版或裸题版的文字，连同附录一的交付要求和说明，一个字节不改地交给智能体，并用校验值核对。
  4. 反问给统一答复。智能体问什么，都回同一句话，并记下它问了什么。见反问和统一答复。
  5. 到时长上限就停。以届时已交付的内容为准。见时长上限。
  6. 留存。保存报告、实际交出的输入、标准错误和运行日志，每次运行在运行记录表（附录四）里加一行，赛后随复核包公开。

主办方运行日用的命令是：

python3 tools/run_agents.py 运行计划.json

申报智能体

冻结截止是运行日前 7 天〔默认〕，以主办方确认为准；具体日期〔待定〕。截止前提交冻结申报表（附录三），此后到比赛结束不得修改智能体。

申报交两样东西：一份申报文件，和系统提示词全文的文件。申报文件是 JSON 文件（一种纯文本的数据格式），每一项对应附录三的一项，另加“调用方式”一项供统一运行程序调用。主办方保存申报材料，算出申报文件和系统提示词文件的校验值，写进每次运行的日志，赛后随复核包公开。涉及商业秘密的部分，可以申请只向复核人公开。

系统提示词全文（另附文件）系统提示词文件文件路径，相对于申报文件所在的目录；文件必须存在。

冻结之后，什么能做、什么不能做

  • 允许：冻结前设计系统提示词、检索策略和工作流程；让智能体专门利用题面中提问者的身份和用途；机械的格式转换，例如把题目文本放进接口的某个字段，须在冻结前申报，对所有题目相同。
  • 不允许：看到题目后改写、补充或删减题目文本；看到题目后修改配置、提示词或工具；针对某一道题或某一个版本单独配置；运行中人工干预，包括回答智能体的提问。想按题调整的，参加开放组。

主办方怎样调用你的智能体

两种方式选一种，写在申报文件的“调用方式”里。每次运行都是全新的进程或请求，不带其他运行的记忆，特别是同一道题的另一个版本。

命令行方式

{"方式": "命令行", "命令": ["python3", "agent.py"], "工作目录": "."}
  1. 每次运行，程序在工作目录里启动一次申报的命令，是一个全新的进程。命令推荐写成列表，一项一个词；也可以写成一行文字。不经过命令解释器，所以不能用管道符号和重定向，需要的话自己写一个脚本。工作目录可以不写，默认是申报文件所在的目录。
  2. 题目全文写进它的标准输入（UTF-8 编码），写完就关闭标准输入。读到输入结束，就得到题目原文。
  3. 写到标准输出的全部内容就是报告，反问行除外。写完退出即可。
  4. 标准错误单独存成日志，可以写进度、检索记录、工具调用这些中间过程。
  5. 环境变量不整份沿用主办方的运行环境，只给一组固定的基本变量（PATH、HOME、LANG、LC_ALL、TMPDIR、USER、SHELL、TERM，主办方环境里有的才给），加上申报文件“需要的环境变量”一项点名的变量，另加一个 REPLY_PIPE，用来反问，见下一节。运行日志只记交出去的变量名，不记值。
  6. 退出状态记进日志。退出状态不是 0，已经写出的报告照样算交付。

网络接口方式

{"方式": "网络接口", "地址": "http://127.0.0.1:8000/run"}
  1. 每次运行，程序向申报的地址发一个请求，方法是 POST，类型是 application/json，字符编码 UTF-8，内容是： 
    {"题目": "题目原文", "往来": []}
  2. 智能体回应其中一种：报告，类型 application/json，内容 {"报告": "报告全文"}，报告是 Markdown 或网页的文字；报告文件本身，类型不是 application/json，例如 PDF 报告回 application/pdf，内容原样存下；反问，内容 {"反问": "问题"}，见下一节。
  3. 回应状态不是 200，或者连不上地址，这次运行算出错、未交付，状态和回应内容记进日志。
  4. 请求里没有会话编号。一次运行里因为反问可能有几个请求，都属于同一次运行；不同运行之间不要共享记忆。

报告存成哪种文件

按报告内容的开头判断，不看你怎样称呼它：以 %PDF 开头的存为 报告.pdf；以 <!doctype html 或 <html 开头的存为 报告.html；其余存为 报告.md。所以网页报告要以这两种写法之一开头，PDF 报告交文件本身。

题目原样交出，逐字核对

  • 交给智能体的是题目文件的全文：提问版或裸题版的文字，后面接附录一的交付要求和说明。程序一个字节不加、不减、不改，换行也照原样。
  • 程序算出实际交出去的文字的校验值，与题目冻结时算好的校验值比对，运行记录的“输入校验值是否一致”一列写“一致”或“不一致”。
  • 命令行方式下，智能体提前关闭标准输入的，只算已经写进去的部分，校验值就会不一致。所以一定要读到输入结束。
  • 不一致的，按规则手册第十节处理：原因在队伍申报的格式转换的，该次运行作废，记为未交付；原因在主办方的，重跑一次。

自己算校验值。正式运行时，校验值由主办方算好。你自己写运行计划、用别的题目文件试跑时，想让程序核对输入，就要自己算出这个文件的校验值，填进运行计划的“校验值”一栏。校验值是用名为 SHA-256 的算法从文件内容算出的一串字符，共 64 个数字和字母；文件哪怕只改一个字节，算出来的也完全不同，所以拿它就能核对交出去的文字与冻结的题目一字不差。在 macOS 上运行 shasum -a 256 题目文件，在 Linux 上运行 sha256sum 题目文件，取输出的第一段。

反问和统一答复

运行中不交互。智能体提问或要求确认研究计划时，一律回复附录二的统一答复，并记下它问了什么：

题目已包含全部信息，请按你的理解直接进行，并在报告中写明你的理解和假设。

命令行方式怎样反问

  1. 在标准输出单独写一行：以 [[反问]] 开头，后面接问题，问题写在同一行；行尾要换行，写完立即刷新输出。
  2. 然后打开环境变量 REPLY_PIPE 给出的文件，读到结束，就得到统一答复（一行文字）。这个文件是一个命名管道，答复送到之前读会一直等着。
  3. 接着调研，继续往标准输出写报告。反问行不算报告内容。
import os
import sys

question = sys.stdin.read()  # 题目原文

print("[[反问]] 你说的最大，是按面积算还是按蓄水量算？", flush=True)
with open(os.environ["REPLY_PIPE"], encoding="utf-8") as pipe:
    reply = pipe.read().strip()  # 统一答复

print("# 主要结论")
print("按面积理解：……")

完整的例子见新手包里的 agent.py。不经过统一运行程序直接启动时，没有 REPLY_PIPE，它就不反问。

网络接口方式怎样反问

  1. 回应 {"反问": "问题"}，类型 application/json。
  2. 程序向同一个地址再发一个请求，内容带上前面的全部往来： 
    {"题目": "题目原文", "往来": [{"反问": "你的问题", "答复": "题目已包含全部信息，请按你的理解直接进行，并在报告中写明你的理解和假设。"}]}
  3. 照常回应报告；也可以再反问，“往来”会一项一项加长。智能体看“往来”就知道自己问过什么、得到了什么答复。

两种方式共同的规矩

  • 每次反问回复一次统一答复，每次都是同一句话。问题全部记进运行记录“智能体是否提问，问了什么”一列和运行日志。
  • 反问的次数不限。一次运行只在智能体自己退出（或交出报告），或者到了时长上限时结束（规则手册第五节）。
  • 等答复的时间算在时长上限之内；答复是立即给的。
  • 只能选择“批准计划”的智能体，在自己的程序里直接批准，不必反问。
  • 不反问也可以。附在题目后面的说明已经写明：本题已包含全部信息，请直接开始，不需要向我确认。

运行环境

全部运行由主办方统一进行〔默认〕，以主办方确认为准。参赛队伍在运行前看不到题目，运行中也不接触智能体。

  • 同一天。全部运行在同一天完成，截止时间就是运行当日。几支队伍同时运行时，同一道题的同一个版本，各队差不多同时开始。运行日〔待定〕。
  • 操作系统。统一运行程序在 macOS 和 Linux 上运行；命令行方式用到命名管道，Windows 不支持。主办方运行机器的具体配置〔待定〕。
  • 你的程序需要什么，写进“运行环境说明”。语言和版本、要装的依赖、要用的环境变量。命令行方式下，你的程序只拿到一组固定的基本环境变量，加上你在申报文件“需要的环境变量”一项里点名的变量，见调用方式。模型和检索服务的密钥怎样交给主办方〔待定〕，定下后在公告页公布。
  • 工具不统一。搜索次数、用时（在时长上限之内）和所用工具不统一，也不计分，属于智能体自身的能力；用到的工具和外部服务列进“工具和外部服务清单”。
  • 日志和存档。主办方保存每次运行的输入、报告、标准错误、起止时间和运行日志。检索记录、工具调用这些中间过程，写到标准错误就能一并留存。报告引用的网页在运行后 24 小时内存档，附存档时间和校验值。
  • 故障重跑〔默认〕，以主办方确认为准。因主办方运行环境的故障中断的，允许重跑一次；智能体自身出错不重跑。由主办方判定，判定理由公开。重跑的结果另存，原来的结果保留，运行记录写明原因。

时长上限

每次运行最长 120 分钟〔默认〕，以主办方确认为准。

  • 从启动命令，或者发出第一个请求开始计时。等反问答复的时间也算在内。
  • 到时立即停止：命令行方式强行结束整个进程组，包括它启动的子进程；网络接口方式不再等待回应。
  • 以届时已交付的内容为准：命令行方式，到那时已经写到标准输出的内容就是报告；网络接口方式，到那时还没收到完整的回应，就是没有交付。
  • 没有交付，或者交付的内容全是空白，记为未交付，运行记录“文件名”一列写“未交付”。
  • 所以命令行方式最好边写边输出、及时刷新，先写主要结论；网络接口方式给自己留出余量，在上限之前回应。

交付要求

每次运行交付一份书面报告，必须包含五个部分。下面是原文，附在每道题的提问版和裸题版之后，一字不改。

交付要求：请交付一份书面报告。版式不限，但必须包含以下五个部分：

1. 主要结论：放在报告开头。

2. 论证与解释。

3. 出处：每个关键结论都标明来源，给出可以点开的网址和取用日期，尽量使用原始出处。

4. 把握程度：主要判断各有多大把握，为什么。

5. 查找与来源说明：你查了哪些方面，用了哪些来源，其中哪些可靠、哪些不可靠，还有哪些信息缺口。

说明：本题已包含全部信息，请直接开始，不需要向我确认。如果有不清楚的地方，请按你的理解进行，并在报告中写明你的理解和假设。

  • 格式。网页、Markdown 或 PDF 中的一种，链接必须保留〔默认〕，以主办方确认为准。篇幅和版式不限。
  • 出处。每个关键结论给出可以点开的网址和取用日期，尽量使用原始出处。
  • 缺少某个部分。不算硬伤，在相应环节的评级中体现。例如没有把握说明，“结论与把握”一环最多 1 档；没有交代查找过程，“查找过程的交代”一环为 0 档。
  • 裸题版的报告。要写明自己对提问者和用途的理解与假设；附在题目后面的说明里已经这样要求。
  • 不进入名次的。篇幅、格式、引用条数、文笔。
  • 交付前自查。新手包里的 check_report.py 检查五个部分齐不齐、主要结论在不在开头。

原文：规则手册第六节 交付要求 · 附录一 统一交付要求和说明 · 纯文字版

封闭组和开放组 〔默认〕

参赛分两组〔默认〕，以主办方确认为准。每支队伍在冻结截止前选定参加哪一组，也可以两组都参加，两组分别申报、分别运行。

  • 封闭组。本页说的全部做法：题目原文原样作为唯一输入，看到题目后不做任何针对题目的调整。主名次只在封闭组内排。
  • 开放组。封闭组全部运行结束后才拿到题目，在主办方规定的期限内调整，再由主办方另定一天统一运行。允许改写题目文本、修改配置或提示词、针对某道题单独配置；运行中人工干预仍不允许。名次按同样的规则排出，单独公布，不与封闭组比较。
  • 开放组同样申报。冻结截止前照常提交冻结申报表。看到题目后做的每一处调整，在运行前交给主办方，写明改了什么、针对哪道题的哪个版本，随复核包公开；运行日志中的输入，与申报的调整后的输入逐字核对。
  • 调用方式两组相同。除了拿到题目的时间和运行日期，第五节的运行规定照常适用，所以调用方式、反问约定和时长上限都与封闭组相同。

随机抽查 〔默认〕

每届随机抽一支队伍〔默认〕，以主办方确认为准，核对它的运行方式和输入与冻结申报一致。

  • 全部运行结束后，主办方用这支队伍冻结申报的版本，即申报表所列的版本号或代码提交号、系统提示词、模型和工具，重跑一道题，核对两件事：调用方式和格式转换与申报表相符；经格式转换后的输入与题目文本逐字一致。重跑的报告只用来核对，不计分。抽签方式和结果写入复核包。
  • 所以冻结的版本要保存好，能原样再跑一次。
  • 查出不一致，原因在队伍的，视同冻结后修改，取消该队全部成绩；原因在主办方的，该队受影响的运行各重跑一次。

新手包

新手包是 starter-kit 文件夹，里面每个文件都能单独打开、下载。先读它的说明。

文件是什么
README.md新手包的说明：里面有什么，怎样原样跑一遍，怎样换成你的智能体。
申报表模板.json冻结申报表的模板，统一运行程序能直接读取。现在填的是示例智能体的情况。
系统提示词.md示例系统提示词，示范申报时要交的系统提示词全文是什么样子。
agent.py示例智能体：命令行方式，演示反问约定，不调用任何模型，报告里写明是示例。
运行计划.json示例运行计划：用示例智能体跑练习题的提问版和裸题版，各一次，并写好两个文件的校验值。
练习题/淡水湖/提问版.txt练习题的提问版，就是交给智能体的全文：出题手册第四节的原文，后面接附录一。
练习题/淡水湖/裸题版.txt练习题的裸题版，同上。
交付要求.txt统一交付要求和说明的原文（附录一）。
check_report.py检查一份报告是否包含交付要求的五个部分，主要结论是否在开头。
check_report.md检查小程序的说明：怎样算有这一部分，能查哪些格式，退出状态。

统一运行程序不在新手包里，它在资料站所在仓库的 tools 目录：程序和使用说明。两者都只用 Python 自带的标准库，不需要装别的包。

练习题原文照抄出题手册第四节实例一，一字不改，“〔运行当日〕”也原样保留。练习题只用来熟悉题目和评法，不进入名次。

用练习题自查

在本机按主办方的办法跑一遍，看运行记录和报告，再检查报告的五个部分。

  1. 原样跑一遍示例。在仓库根目录运行下面的命令，一两秒就跑完。运行记录里有两行，“输入校验值是否一致”都是“一致”，示例智能体各反问了一次。 
    python3 tools/run_agents.py site/starter-kit/运行计划.json
  2. 换成你的智能体。复制申报表模板，按你的智能体填写每一项，改调用方式；在运行计划的“智能体”里换成你的申报文件。想快一点试通，可以临时把运行计划里的时长上限改小。
  3. 检查报告。结果在 site/starter-kit/运行结果 下面，按日期、队伍、题目、版本分开。把下面命令里的“示例队”换成你的队伍名称： 
    python3 site/starter-kit/check_report.py site/starter-kit/运行结果/*/示例队/淡水湖/*/报告.md
  4. 看报告怎样走到名次。跟着淡水湖这道题，看评委怎样判定、怎样算出名次区间。一道题走完全程

同一天再跑一遍，已经有结果的运行会被跳过；想从头再跑，先删掉 运行结果 目录。详见新手包的说明。
