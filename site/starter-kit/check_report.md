# 检查报告的小程序

程序是同目录的 `check_report.py`，检查一份报告是否包含交付要求的五个部分。只用 Python 自带的标准库，不需要装别的包。测试在仓库根目录的 `tests/test_starter_kit.py`。

它只帮你在交付前自查。评审不用它，评委看的是报告本身；它判“不合格”，也不等于报告缺了这一部分。按[规则手册](../../notes/rules.html)第六节，缺少某个部分不算硬伤，在相应环节的评级中体现，例如没有把握说明，“结论与把握”一环最多 1 档。

## 用法

在新手包目录里运行：

```
python3 check_report.py 报告.md
```

一次可以检查几份：

```
python3 check_report.py 报告一.md 报告二.html
```

输出每一份报告的五个部分有没有找到，最后一行是结论：

```
报告.md
  有　主要结论（放在开头）
  有　论证与解释
  缺　出处
  有　把握程度
  有　查找与来源说明
  结论：不合格。缺少：出处。
```

## 检查什么

五个部分取自[交付要求原文](交付要求.txt)（规则手册附录一）：

1. 主要结论，放在报告开头；
2. 论证与解释；
3. 出处；
4. 把握程度；
5. 查找与来源说明。

**怎样算有这一部分。** 报告里有一行是这一部分的标题。下面几种写法都算：

- Markdown 的标题，例如 `## 主要结论`、`## 1. 主要结论`、`## 一、主要结论`、`## 出处与引用`；
- 网页的标题（`h1` 至 `h6`），写法同上；
- 单独成行的名称，或者名称后面跟冒号，例如 `**把握程度**：……`、`出处：……`。

名称要用附录一的写法。正文句子里提到名称不算，例如“主要结论是鄱阳湖”不算有“主要结论”这一部分。

**主要结论要在开头。** 五个部分里，主要结论必须最先出现。报告的标题、日期写在它前面没有关系。其余四个部分的先后不限。

**提醒：没有网址。** 报告里一个 `http://` 或 `https://` 开头的网址也没有，会多打一行提醒。出处要给每个关键结论标明可以点开的网址和取用日期。提醒不影响结论。

## 能检查哪些格式

| 报告 | 能不能检查 |
| --- | --- |
| Markdown 或纯文字 | 能 |
| 网页（以 `<!doctype html` 或 `<html` 开头） | 能，按网页的标题和段落拆行 |
| PDF（以 `%PDF` 开头） | 不能。请检查生成 PDF 之前的 Markdown 或网页原稿 |

格式按文件内容的开头判断，与[统一运行程序](../../tools/run_agents.md)判断报告文件类型的办法相同，不看文件名。文字要用 UTF-8 编码。

## 退出状态

| 退出状态 | 意思 |
| --- | --- |
| 0 | 全部合格 |
| 1 | 至少一份不合格 |
| 2 | 至少一份读不了，例如 PDF、文件不存在、不是 UTF-8 编码 |

在自己的脚本里，可以用退出状态判断要不要停下来改报告。
